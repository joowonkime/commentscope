# CommentScope — 지금까지 만든 것

**댓글에서 관점을 묶고, 각 관점의 근거로 답하는 Agent를 만드는 파이프라인 초안을 구현했습니다.** 제한된 실제 자료에서 두 Agent의 질문·답변·원문 조회까지 확인했습니다. 전체 댓글을 자동으로 잘 묶는 품질은 아직 목표에 도달하지 못했습니다.

현재 저장소는 이 초안을 조원들이 받아 함께 고치는 공통 시작점입니다.

## 그래서 지금까지의 결론은?

| 궁금한 점 | 현재 답 |
| --- | --- |
| 무엇을 만들었나? | 댓글 입력 → 관점 후보 추출 → 후보 통합 → 원문별 지지 확인 → 이유·조건 정리 → Agent 생성 → 질문·근거 조회 코드 |
| 실제로 확인한 것은? | 기존 UBI 영상 하나에서 Agent 2개·각 유효 지지 댓글 3개의 제한된 경로와 실제 6응답·웹 API 연결 |
| 이제 완성인가? | 개발 초안이다. 전체 댓글의 관점을 충분히 살리는 자동 분석 품질과 팀 프론트 통합·사용자 테스트가 남았다. |
| 다른 조원이 할 수 있는 일은? | 합성 화면 확인, 특정 모듈 수정, 프론트/API 연결, 결과 검토·테스트 설계 |
| 모델 없이 실행되나? | 아래 합성 데모와 코드 검사는 가능하다. 실제 댓글 자동 분석에는 별도 자료와 모델 환경이 필요하다. |

## 코드 몰라도 수정 요청하기

이 저장소를 내려받아 코딩 에이전트에서 폴더를 연 다음 아래처럼 요청합니다. 수정할 내용만 바꿔 적으면 됩니다.

> README.md와 AGENTS.md를 읽어줘. 내가 원하는 변경은 [수정할 내용]이야. 기존 작업을 보존하고 별도 작업 브랜치에서 구현·검사한 뒤 GitHub에 PR까지 만들어줘. 결과는 비개발자가 이해할 말로 설명해줘.

[AGENTS.md](AGENTS.md)에 작업 브랜치 생성 → 수정 → 검사 → PR 제출 절차를 설정했습니다. 온라인 제출에는 GitHub 로그인과 저장소 쓰기 권한 또는 fork 권한이 필요합니다. 실제 작업은 에이전트에 변경을 요청했을 때 시작됩니다.

구체적인 절차는 [조원 시작 안내](docs/TEAM_START.md), 수정 위치는 [파이프라인 개발 안내](docs/PIPELINE_DRAFT.md)를 봅니다.

## 화면으로 확인하기

Python 3.12 이상에서 저장소의 `src` 폴더로 이동해 실행합니다. GPU·모델·API 키·추가 패키지는 필요 없습니다.

```bash
cd src
python -m commentscope.agents.team_demo --session-dir ../runs/team-demo
```

브라우저에서 **http://127.0.0.1:8766**을 엽니다. 두 관점을 선택하고 `핵심 입장은 무엇인가요?`, `이유와 조건은 무엇인가요?`, `정확한 시행 비용은?`을 물어보세요. 근거가 없는 질문에는 보류하고, 원문 버튼으로 근거를 확인합니다. 종료는 `Ctrl+C`입니다.

**이 화면은 합성 예시입니다.** 미리 만든 댓글·Agent·응답을 사용하며 실제 클러스터링이나 모델 품질을 시연하지 않습니다. 실제 자료에서 확인한 범위는 [상세 현황](docs/TEAM_STATUS.md)에 기록했습니다.
