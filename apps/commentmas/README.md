# CommentMAS — 배포된 시연 서비스 소스

이 폴더는 https://commentmas.vercel.app 에 배포한 독립 React/Python 시연 앱입니다.
저장소 루트에서 `cd apps/commentmas` 후 아래 명령을 실행합니다.

공유 범위와 기존 CommentScope 구현과의 관계는 [소스 반입 기록](IMPORT.md)을 확인하세요.
`.env`, Firebase 웹 환경 설정, 실제 댓글/분석 결과, 개인 대화·회고, 인증 캐시는 포함하지 않습니다.
새 clone에서 실제 모델 대화를 실행하려면 API 키와 별도 분석 자료가 필요합니다.
분석 자료를 기존 경로에 제공하거나 `--data PATH`로 지정하세요. 합성 자료를 사용하는 Python 회귀 테스트는 자료·키 없이 실행할 수 있습니다.

유튜브 댓글의 다양한 관점을 탐색하는 멀티에이전트 시스템입니다.
`Milestone3_Report.pdf`의 Explore → Converse → Reflect 흐름을 참고합니다.
현재 구현 범위는 **댓글 수집, 필터링, 관점 그룹핑, 관점별 에이전트, React 기반 Step1·Step2 화면과 실제 대화 연결**입니다.

백엔드는 Python 3.10 이상에서 외부 패키지 설치 없이 실행합니다. 웹 화면은 Node.js 22.12 이상과 npm을 사용합니다.

## 시연 링크 배포

시연 링크: **https://commentmas.vercel.app**

Firebase 프로젝트는 `YJ-MAS` (`review-agents-20261124`), 웹 앱은 `CommentMAS`입니다.
화면은 Vercel, 기존 Python API는 Cloud Run, 대화·회고·저장한 근거는 Firestore를 사용합니다.
시연에는 로그인 화면이 없습니다. Firebase의 익명 세션으로 브라우저별 기록을 분리합니다.
기존 로컬 대화 기록은 자동 업로드하지 않습니다.

배포 전 계정 연결:

- 해당 Google Cloud 프로젝트에 결제 계정 연결
- Vercel 계정 인증

Firebase 연결 설정은 `scripts/setup_firebase.py`가 `frontend/.env.production.local`에 생성하며, 이 파일은 Git과 서버 빌드에서 제외합니다.
서버용 키는 웹 화면에 넣지 않습니다. Cloud Run은 전용 서비스 계정과 Secret Manager를 사용합니다.

```bash
# 최초 설정을 다시 준비해야 할 때:
python3 scripts/setup_firebase.py --project review-agents-20261124 --name YJ-MAS --app-name CommentMAS

# 결제 연결 후 API 배포 (현재 활성 gcloud 계정 사용):
python3 scripts/deploy_backend.py
```

API 배포 스크립트는 익명 세션 설정, 전용 서비스 계정, 모델 키의 Secret Manager 저장,
Firestore 접근 규칙과 Cloud Run 배포를 처리하고 `frontend/vercel.json`에 API 경로를 설정합니다.
서버는 백그라운드 대화를 위해 CPU 할당을 유지하며, 유휴 시 0개·최대 1개 인스턴스로 구성합니다.
작업 상태는 서버 메모리에 있으므로 서버 교체 시 진행 중 요청은 재시도가 필요할 수 있습니다.
대화 본문은 각 저장 시 Firestore에 기록하며 큰 기록은 압축하여 여러 문서에 나눠 저장합니다.

현재 Vercel 프로젝트는 `angelas-projects-91a6cf82/commentmas`입니다.
`python3 scripts/deploy_frontend.py`로 프런트엔드를 다시 배포할 수 있습니다.
이후 `frontend`를 Vercel의 Vite 프로젝트로 배포합니다. Vercel 빌드 환경에도
`frontend/.env.example`의 `VITE_FIREBASE_*` 네 값을 동일하게 설정해야 합니다.
배포 후 Cloud Run의 `ALLOWED_ORIGINS`에 실제 Vercel HTTPS 주소를 설정합니다.
Firebase SDK 키는 공개 웹 설정이고, 모델 API 키와 Firebase 관리 권한은 서버에만 둡니다.

검증: Python 단위·API 테스트, 프런트엔드 빌드, Playwright 회귀 테스트를 실행합니다.
실제 Firestore의 저장·조회·수정·동시 수정 방지·삭제도 별도 임시 기록으로 확인했습니다.

## React 웹 화면 실행

Figma MAS의 Step1·Step2를 React + TypeScript + Vite로 구현했습니다.
레이아웃·보라색 테마·아바타·아이콘은 디자인을 따르고, 숫자와 요약은 실제 분석 결과를 사용합니다.
현재 데이터는 수집 1,217개, 유지 1,150개, 그룹 배정 863개, 그 외의 의견 287개입니다.
기타 의견은 여섯 번째 agent가 되지 않습니다. 5% 미만 제거 규칙도 적용하지 않습니다.

최초 준비:

```bash
cd frontend
npm install
npm run build
cd ..
python3 prepare_web.py
python3 web_server.py
```

브라우저에서 **http://127.0.0.1:8000** 을 엽니다. 이후에는 `python3 web_server.py`로 다시 실행하면 됩니다.
화면 코드를 변경했다면 `frontend`에서 `npm run build` 후 새로고침합니다.
시연 서버에는 영어 표시 데이터를 준비했으며, 공유 소스에는 포함하지 않습니다. 별도 자료로 `prepare_web.py` 재실행 시 동일 입력의 캐시를 재사용합니다.
다른 분석 폴더를 사용하려면 준비와 실행에 동일한 `--data PATH`를 지정합니다.

개발 중에는 API 서버를 실행한 상태에서 별도 터미널의 `frontend` 폴더에서 `npm run dev`를 실행합니다.
개발 화면 주소는 http://127.0.0.1:5173 입니다. `/api` 요청은 Python 서버로 프록시합니다.

웹에서 지원하는 흐름:

- 초기 의견 작성·수정 → Step1의 5개 관점 카드, 댓글·좋아요 분포, 대표 댓글·그룹 내부 차이 확인.
- 관점 카드 클릭 → 내 초기 의견과 유사점·차이점·추가로 생각할 질문을 모델로 비교.
  인용 강조는 사용자가 쓴 정확한 문구만 사용합니다.
- 1:1 또는 2~5개 agent 그룹 대화 생성 → 기존 `ChatSession`과 `PerspectiveAgent`로 실제 응답.
- 그룹의 첫 응답 후 agent 간 토론 → Pause → 한 개 이상의 응답 대상 선택·후속 질문 → Resume.
  한 번 Resume할 때 최대 6개 자동 발언 후 멈춥니다. Pause를 누르면 진행 중인 응답은 마치고 다음 발언을 시작하지 않습니다.
- 답변의 Evidence 클릭 → 해당 agent 소속 원본 댓글의 영어 번역·한국어 원문·YouTube 링크 확인.
  근거 저장·다시 보기, 대화 검색·종류 필터, 대화 재개, 실패한 agent만 재시도를 지원합니다.
- Other opinions에서 그룹에 억지로 배정하지 않은 댓글을 페이지별로 확인합니다.

화면·요약·비교·agent 응답과 추천 후속 질문은 영어입니다. 한국어 원문은 사용자가 `Show Korean original`을 눌렀을 때만 표시합니다.
영어 질문은 검색용 한국어로 한 번 번역해 각 agent의 한국어 댓글 검색에 사용하며, 사용자 메시지 원문은 유지합니다.
원문 댓글·기존 그룹·agent bundle은 수정하지 않고 표시 번역을 별도 캐시에 저장합니다.
모델이 한국어 답변을 반환하면 수용하지 않고 한 번 재시도합니다.

웹 데이터는 분석 폴더의 `04_web/`에 저장됩니다:

| 위치 | 내용 |
| --- | --- |
| `catalog.json` | 실제 분석과 연결된 영어 화면 요약·통계·대표 댓글 |
| `translations.json` | 텍스트·언어 기준 번역 캐시 |
| `comparisons/` | 초기 의견과 관점별 비교 캐시 |
| `rooms/` | 참가 agent, 초기 의견, 대화·근거, Pause 상태 |

초기 의견 입력과 저장한 근거 목록은 같은 브라우저의 localStorage에 보존합니다.
기존 대화의 초기 의견과 참가자는 고정되어 있고, 의견 수정은 새 대화에 적용됩니다.
API 키는 Python 서버에서만 읽으며 React 빌드나 API 응답에 포함하지 않습니다.
카탈로그 읽기·대화 목록·대화 재조회는 모델을 호출하지 않습니다.
새 비교·질문·토론·캐시에 없는 댓글 번역에는 `.env`의 모델 API 사용료가 발생합니다.

Explore·Converse·Reflect와 배포 연결을 구현했습니다. 외부 통계·보고서 검색은 이후 범위입니다.
근거 패널에는 agent가 실제로 인용한 댓글만 표시합니다.

실제 모델을 사용하는 브라우저 검증:

```bash
node scripts/verify_web.mjs
```

생성되는 `screenshots/` 보고서와 개인 대화는 Git에 포함하지 않습니다.
Chrome이 설치된 환경에서 Step1, 비교, 1:1·그룹 토론, Pause·Resume, 선택 응답, 근거, 저장·재개와 모바일 화면을 검증합니다.
이 명령은 실제 API를 호출합니다. 결과와 스크린샷은 `screenshots/react-*`로 저장합니다.

모델 호출 없는 웹 회귀 테스트는 `frontend`에서 `npm run test:e2e`로 실행합니다.
관점 비교, 한국어 원문 표시, 그룹 선택 제한, 성공한 응답을 보존하는 재시도, 근거 저장과 모바일 화면을 확인합니다.
Python 테스트에는 영어 응답 검증, 번역 캐시·ID 검증, 중복 요청 방지, 토론 상한과 진행 중 Pause도 포함합니다.

## 단계별 구현 범위

1. **필터링 — 구현됨.** 의견이 있는 댓글을 보존하고 명확한 저가치 댓글을 제외합니다.
2. **관점 그룹핑 — 구현됨.** 같은 주제라도 입장과 논거가 다르면 구분합니다.
   4~5개 그룹을 지향하고, 최대 5개로 제한합니다. 실제 데이터에 없는 관점을 만들어
   개수를 채우지 않습니다. 복합 의견과 소수 관점은 별도 표시해 보존합니다.
3. **Perspective Agent 초안 — 구현됨.** 각 그룹의 원본 댓글, 대표 입장, 논거,
   내부 차이와 근거를 가진 독립 에이전트를 생성합니다. 1:1·선택한 여러 에이전트와의 대화,
   제한된 횟수의 에이전트 간 토론, 대화 저장·재개를 지원합니다.
   React 웹 UI와 사용자 의견 비교 화면도 구현했습니다. Reflect 분석은 아직 구현하지 않았습니다.

보고서의 기존 1,130개/5개 그룹과 5% 기준은 준비된 프로토타입 시나리오입니다.
필터 결과를 그 수치에 맞추거나 5% 미만 의견을 자동으로 제거하지 않습니다.

## 설정과 수집

`.env`에 다음 이름으로 키를 설정합니다. 실제 값은 커밋하지 않습니다.

```dotenv
YOUTUBE_API_KEY=...
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-6.2-sol
OPENAI_REASONING_EFFORT=medium
# 대체 제공자를 사용할 때만 설정:
# OPENROUTER_API_KEY=...
# OPENROUTER_MODEL=openai/gpt-4.1-mini
```

OpenAI 키가 있으면 기본적으로 OpenAI Responses API에 직접 연결합니다.
기본 모델은 `gpt-6.2-sol`, 추론 강도는 `medium`입니다.
`--provider openai` 또는 `--provider openrouter`로 명시할 수 있고,
`.env`의 `LLM_PROVIDER`로 기본 제공자를 지정할 수도 있습니다.
선택한 제공자에서 오류가 나면 중단하며 다른 제공자로 자동 전환하지 않습니다.

```bash
python3 collect_comments.py "https://www.youtube.com/watch?v=VIDEO_ID"
```

수집한 원본은 `data/<video_id>_<timestamp>.json`과 CSV로 저장됩니다.
필터링에는 JSON을 사용합니다. 공개 댓글과 대댓글을 수집하며,
삭제·비공개 댓글이나 API에서 제공하지 않는 내용은 포함되지 않습니다.

## 1단계: 필터링

먼저 소규모 결과를 검토할 수 있습니다. 입력 경로는 실제 수집 파일로 바꿉니다.

```bash
python3 filter_comments.py data/BAHKmi4F1L8_20261026-144540.json --max-comments 60 --output data/processed/filter_preview
```

전체 실행:

```bash
python3 filter_comments.py data/BAHKmi4F1L8_20261026-144540.json
```

영상 제목으로 논점을 판단하기 어려우면 `--topic "주4일·4.5일제의 도입과 근무시간 단축"`을
추가합니다. 모델은 `--model` 또는 선택한 제공자의 `OPENAI_MODEL` / `OPENROUTER_MODEL`로
바꿀 수 있습니다. OpenAI는 `gpt-6.2-sol`, OpenRouter는 `openai/gpt-4.1-mini`처럼 이름을 씁니다.
OpenAI의 추론 강도는 `OPENAI_REASONING_EFFORT=low|medium|high`로 설정합니다.
댓글 원문·부모 댓글·영상 제목을 선택한 API 제공자에게 전송하므로 API 사용료가 발생합니다.
작성자와 좋아요 수는 모델에 보내지 않습니다. OpenAI 요청은 `store=false`를 사용합니다.

### 분류 기준

| 결과 | 기준 |
| --- | --- |
| `keep` | 관련된 입장·제안·우려·경험·논거·의미 있는 질문이 있음 |
| `exclude` | 명백한 빈 내용, 웃음·기호만 있는 반응, 스팸, 무관한 내용, 의견 없는 농담·반응 |
| `review` | 문맥 부족, 모호한 풍자, 판단 신뢰도 부족, 너무 긴 댓글, 오프라인 미분류 |

- `ㅋㅋ`, 욕설, 짧은 길이, 소수 의견, 낮은 좋아요 수만으로 제외하지 않습니다.
- 예: `ㅋㅋ 임금은 누가 줌?`, `10-5해줘`는 규칙으로 제외하지 않고 의미를 판단합니다.
- 의견의 진위나 찬반 방향을 평가하지 않습니다. 댓글은 외부 사실의 검증 자료가 아닙니다.
- 모델이 제외하려는 댓글은 별도 API 요청으로 한 번 더 검토합니다. 재검토에서 의견이 발견되면
  유지하고, 관련성이 모호하면 검토 대상으로 돌립니다. 최초 판정도 `first_pass`에 남깁니다.
  이 절차는 오제외를 줄이기 위한 보완이며 정확도를 보장하지 않습니다.
- 대댓글은 원본 데이터의 부모 댓글을 함께 전달합니다. 문맥이 없으면 검토 대상으로 둡니다.
- 서로 다른 ID의 동일 문구는 보존합니다. 그래야 이후 댓글 수와 좋아요 분포가 왜곡되지 않습니다.
- 모델 신뢰도가 기본 `0.75` 미만이면 유지·제외 판정을 모두 `review`로 전환합니다.
  이 수치는 모델의 자기평가이며 실제 정확도를 보장하지 않습니다. `--review-threshold`로 조정합니다.
- 원문은 삭제·축약하지 않습니다. `review`는 `filtered.json`에 자동 포함되지 않으므로
  그룹핑 전 검토하고 처리 방침을 확정해야 합니다. 현재 수동 검토 결과를 자동 적용하는 기능은 없습니다.

### 결과 파일

기본 위치: `data/processed/<입력 파일명>/01_filter/`

| 파일 | 내용 |
| --- | --- |
| `filtered.json` | 유지된 원본 댓글과 실행 메타데이터; 다음 단계의 입력 후보 |
| `review.json` | 검토가 필요한 원본 댓글 |
| `excluded.json` | 제외된 원본 댓글 |
| `decisions.json` | 모든 원본 댓글, 판정·유형·이유·신뢰도·분류 방식 |
| `decisions.csv` | 판정과 원문을 나란히 검토하는 표 |
| `.cache/` | 검증된 모델 배치 응답; 실패 후 재실행 시 재사용 |

각 댓글은 세 결과 중 하나에 정확히 한 번만 속합니다. 원본 작성자·ID·부모 ID·좋아요·시각 등은
JSON에 그대로 보존합니다. 원본 파일은 수정하지 않습니다.
메타데이터에는 정책 버전, 입력 해시, 전체/처리 수, 부분 실행 여부, 모델과 새 요청의 사용량을 기록합니다.
`--max-comments`는 대댓글 포함 앞쪽 N개만 처리하는 미리보기이며 대표 표본이 아닙니다.
미리보기에는 `is_partial: true`가 기록됩니다.

배치는 기본 30개이며 원문 길이에 따라 더 작게 나뉩니다. 제외 후보 재검토에는 추가 API 호출이 발생합니다.
독립 배치를 동시에 처리하려면 `--workers 3`을 추가합니다. 기본값은 1이며,
동시 처리에서도 최종 댓글 순서는 원본과 같습니다. 완료된 배치는 개별적으로 캐시에 저장합니다.
누락·중복 ID, 잘못된 스키마,
미완성 응답은 결과로 채택하지 않습니다. 실행이 실패하면 같은 명령으로 다시 실행합니다.
모델에는 배치 안에서만 쓰는 짧은 임시 ID를 전달하고, 검증 후 원래 유튜브 ID로 복원합니다.
기존의 검증된 원본 ID 응답 캐시도 재사용합니다.
같은 입력·주제·모델·제공자·추론 강도·배치·프롬프트의 검증된 응답은 캐시를 재사용하고,
이 설정이 바뀌면 다시 분류합니다. 출력 경로가 다르면 캐시는 공유하지 않습니다.
동일 출력 폴더에 여러 실행을 동시에 쓰지 마세요.

API 없이 입출력 구조만 확인:

```bash
python3 filter_comments.py data/BAHKmi4F1L8_20261026-144540.json --offline --output data/processed/offline_check
```

오프라인 모드는 명백한 빈 내용·반응만 제외하고 나머지는 전부 `review`로 둡니다.
LLM 의미 필터링 결과와 구분해야 합니다.

## 2단계: 관점별 그룹핑

```bash
python3 group_comments.py data/processed/BAHKmi4F1L8_20261026-144540/01_filter/filtered.json --provider openai --model gpt-6.2-sol --workers 3
```

기본 출력은 같은 영상 폴더의 `02_group/`입니다. `--output`으로 바꿀 수 있습니다.
입력은 1단계의 `filtered.json`만 받습니다. 1단계 검토 댓글은 자동 포함하지 않습니다.
부모 댓글은 1단계 메타데이터가 가리키는 원본 수집 JSON에서 읽고 입력 해시와 일치하는지 확인합니다.
다른 위치의 원본을 쓸 때는 `--context-source`를 지정합니다. 원본과 필터 결과는 수정하지 않습니다.

### 처리 순서

1. 전체 유지 댓글을 읽어 관점 구분 기준을 찾습니다. 일부 인기 댓글만으로 기준을 만들지 않습니다.
2. 그 기준에 따라 모든 댓글을 배정합니다. 기본 배치는 40개이며 독립 배치 3개를 동시에 처리합니다.
3. 그룹별 실제 구성원을 다시 읽고 대표 입장·논거·내부 차이를 정리합니다.
   논거마다 원본 댓글 ID가 연결되며 원문은 코드에서 그대로 첨부합니다.

그룹 수는 4~5개를 지향하고 **최대 5개**로 제한합니다. `--max-groups 4`처럼 상한을 낮출 수 있습니다.
동질적인 소규모 데이터에서는 억지로 그룹 수를 늘리지 않습니다. 비어 있는 그룹도 최종 결과에 남기지 않습니다.
그룹 이름은 댓글에서 발견한 관점을 설명하며 사람의 이름·직업·성격을 만들어 붙이지 않습니다.

### 배정 기준과 한계

- 같은 주제라도 결론이 반대면 구분합니다. 예를 들어 주4일제 도입과 매일 퇴근시간 단축은
  근무시간이라는 같은 주제를 다루지만 서로 다른 대안일 수 있습니다.
- 명확히 들어맞는 댓글만 **주 그룹 하나**에 배정합니다. 복합 의견에는 최대 두 개의 보조 관점을
  기록하되 댓글 수에 중복 집계하지 않습니다.
- `core`는 그룹 입장에 명확히 부합, `mixed`는 복합 의견입니다. `peripheral`은 기존 관점과
  거리가 있는 주변·소수 관점, `uncertain`은 문맥이나 입장이 불분명한 경우입니다.
- `peripheral`·`uncertain` 또는 신뢰도 기본 0.75 미만은 **그 외의 의견**으로 남깁니다.
  이 댓글의 `primary_group_id`는 `null`, `status`는 `other`이며 실제 그룹에 포함하지 않습니다.
  이는 여섯 번째 관점이나 에이전트가 아닙니다. 원문과 개별 관점 요약은 그대로 보존합니다.
  `proposed_group_id`는 모델이 제안했던 가까운 후보를 남긴 진단 정보일 뿐 실제 소속이 아닙니다.
  기존 옵션명 `--review-threshold`로 배정 기준을 바꿀 수 있고, 신뢰도는 모델의 자기평가입니다.
- 최대 5개라는 제약 때문에 모든 소수 관점을 독립 그룹으로 만들 수는 없습니다.
  원문·개별 관점 요약·보조 관점·그룹 내부 차이를 남겨 대표 의견과 다른 견해도 추적할 수 있게 합니다.
  5% 미만이라는 이유로 댓글을 제거하지 않습니다.
- 그룹 대표 입장과 논거, 내부 차이의 근거는 실제로 배정된 구성원만 사용합니다.
  맞는 구성원이 없는 그룹은 만들지 않으며, 모든 댓글이 맞지 않으면 전부 그 외의 의견으로 남길 수 있습니다.
- 댓글 수와 좋아요 비율의 분모는 **입력된 유지 댓글 전체**입니다. 관점 그룹과 그 외의 의견을
  합쳐 100%가 되며, 영상 전체 댓글이나 영상 좋아요 수의 비율은 아닙니다.
- 댓글 의미를 LLM이 판단하므로 경계가 겹치거나 잠정 배정이 틀릴 수 있습니다.
  구조 검증은 의미 분류의 정확도를 보장하지 않습니다.

### 결과 파일

| 파일 | 내용 |
| --- | --- |
| `groups.json` | 최대 5개 그룹과 별도 `other_opinions` 목록; 그룹별 원본·대표 입장·논거·근거·분포 |

1단계의 `review.csv`는 필터 통과 여부가 미정인 댓글이고,
2단계의 `other_opinions.csv`는 필터를 통과했지만 관점 그룹에 들어맞지 않는 댓글입니다.
출력 정책 v2부터 기존 v1의 잠정 배정은 그 외의 의견으로 분리하고, 예전 2단계 `review.csv`는 갱신 시 제거합니다.
기존의 모델 후보·적합도 응답은 재사용할 수 있지만 그룹 요약은 실제 구성원에 맞춰 새로 생성합니다.

결과에서는 최대 그룹 수, 댓글별 단일 주 그룹 또는 미배정 상태, 원문 보존, 그룹+기타의 완전하고
중복 없는 분할, 분포 계산, 근거 ID의 실제 그룹 소속, 그 외의 의견의 그룹 근거 사용 금지를 검증합니다.
형식·ID 검증이 실패한 모델 응답은 한 번만 다시 요청하고, 또 실패하면 중단합니다.
이미 완료한 단계와 배치는 캐시에 남아 재실행할 때 다시 과금되는 요청을 줄입니다.

이 소규모 사례의 통과 결과를 전체 실제 댓글의 정확도로 일반화하지 않습니다.

## 3단계: 에이전트 생성과 대화

에이전트 생성은 검증된 그룹 데이터를 조립하는 로컬 작업이며 모델 호출이 없습니다.

```bash
python3 build_agents.py data/processed/BAHKmi4F1L8_20261026-144540/02_group/groups.json
python3 chat_agents.py --list
```

에이전트 목록은 g1~g5입니다. g1은 근무일 단축, g2는 매일의 시간 단축,
g3는 기존 제도 개선, g4는 업종별 운영, g5는 임금·고용·생산 여건 관점입니다.
이 이름은 현재 영상의 실제 그룹에서 가져옵니다. 다른 영상에서는 다른 그룹이 생성될 수 있습니다.

1:1 대화:

```bash
python3 chat_agents.py --agents g2
```

그룹 대화:

```bash
python3 chat_agents.py --agents g1 g5
```

처음에 출력되는 대화 파일 경로를 저장하면 같은 방을 이어갈 수 있습니다.

```bash
python3 chat_agents.py --session data/processed/BAHKmi4F1L8_20261026-144540/03_agents/sessions/SESSION_ID.json
```

질문 한 번을 보내고 종료하는 방식도 지원합니다.

```bash
python3 chat_agents.py --agents g1 g5 --ask "임금을 유지하고 근무일을 줄이려면 어떤 조건이 필요할까요?"
```

`--initial-opinion "나의 초기 의견"`을 지정하면 방에 저장하고 대화마다 참고합니다.
`--provider`와 `--model`을 생략하면 기존 `.env` 설정을 사용합니다. 현재 기본값은 OpenAI Sol입니다.
생성된 묶음이 여러 개이면 `--registry /경로/agents.json`으로 선택해야 합니다.

### 대화 명령

| 명령 | 기능 |
| --- | --- |
| `/to g1,g5` | 현재 방의 참여자 중 다음 질문에 답할 에이전트 선택 |
| `/sources m0003` | 해당 답변에 연결된 원본 댓글과 유튜브 댓글 링크 확인 |
| `/sources` | 가장 최근 에이전트 답변의 원문 근거 확인 |
| `/history` | 저장된 대화 내용 확인 |
| `/debate 1` | 선택된 에이전트가 서로의 최근 발언에 한 번씩 응답 |
| `/retry m0001` | 질문에 아직 답하지 못한 에이전트만 재시도; 성공한 답변은 재사용 |
| `/exit` | 대화를 저장한 상태로 종료 |

다른 참여자로 대화하려면 새 방을 만듭니다. 기존 방의 참여자를 조용히 바꾸지 않습니다.
토론은 한 명령에 1~3라운드만 진행합니다. `--ask`와 `--debate-rounds 1`을 함께 쓸 수도 있습니다.
에이전트끼리의 토론도 명시적으로 요청했을 때만 진행되며, 각 답변은 누구의 발언에 응답하는지 기록합니다.

### 에이전트 내부 구조

각 `PerspectiveAgent`는 자기 그룹의 **전체 원본 댓글**, 대표 입장, 근거가 연결된 논거,
그룹 내부의 차이와 한계를 가집니다. 현재 다섯 에이전트가 소유한 댓글은 총 863개입니다.
**그 외의 의견 287개와 1단계 필터 검토 55개는 어떤 에이전트에도 넣지 않습니다.**

- 대화 시 질문과 관련된 자기 댓글을 한국어 단어·글자쌍 검색으로 찾아 기본 최대 12개를 전달합니다.
  관련도가 약하면 그룹의 대표 근거를 보완합니다. 댓글 작성자·좋아요 수는 모델에 전달하지 않습니다.
- 다른 에이전트의 발언은 대화 맥락으로 읽을 수 있지만 다른 그룹의 원문 저장소를 근거로 쓰지 않습니다.
  원문 부모가 자기 그룹에 있을 때만 함께 전달합니다. 그렇지 않은 짧은 대댓글에는 문맥 제약이 있습니다.
- 답변은 댓글 기반 내용·명시적인 추론·자료 부족 설명으로 구분해 저장합니다.
  댓글 기반 답변에는 현재 검색한 자기 원문의 ID가 반드시 붙어야 합니다.
  프로그램이 정확한 원문을 첨부하므로 모델이 원문 인용을 만들어내지 않습니다.
- 자기 관점은 유지하되 반론과 조건을 인정하도록 합니다. 실제 댓글 작성자나 특정 직업의 사람을
  사칭하거나 개인 경험을 만들어내지 않습니다. 외부 연구·통계·현재 법률은 새로 검증하지 않습니다.
- 같은 질문에 대한 첫 답변들은 동일한 대화 스냅샷에서 각각 생성합니다. 이후 사용자가 요청한
  토론에서는 다른 에이전트의 발언을 지정해 응답합니다.
- 전체 대화는 로컬 JSON으로 보존하고, 모델에는 최근 20개 메시지와 관련된 과거 메시지 최대 4개를
  전달합니다. 초기 의견도 함께 전달합니다. 에이전트별 발언 인덱스와 방별 기록을 분리합니다.
- 답변 일부가 실패해도 질문과 성공한 답변은 저장합니다. 재시도 시 같은 대상에게 같은 답변을
  다시 호출하지 않습니다. 대화 파일 하나는 한 프로세스에서 사용하세요.

댓글 ID와 소속 검증은 답변의 의미가 항상 원문을 정확히 설명한다는 보장은 아닙니다.
원문 패널에 해당하는 `/sources`로 실제 연결을 확인하고 응답 품질을 평가해야 합니다.
대화에는 모델 API 사용료가 발생합니다.

### 저장 파일

기본 위치는 영상 폴더의 `03_agents/`입니다.

| 파일 | 내용 |
| --- | --- |
| `agents.json` | 전체 에이전트 묶음, 소속 댓글과 관점·논거·지침 |
| `profiles/g1.json` 등 | 에이전트 하나의 전체 데이터 |
| `sessions/SESSION_ID.json` | 방 참여자·초기 의견·대화·원문 근거·에이전트별 발언 기록·사용량 |

같은 내용의 에이전트를 다시 생성해도 기존 방을 재개할 수 있습니다.
관점·댓글·지침이 달라지면 새 묶음으로 판단하므로 원래 묶음을 사용하거나 새 방을 만들어야 합니다.
프로필 파일은 내부 구조 초안입니다. 이름·말투·대화 정책은 이후 제품 설계에 맞춰 조정할 수 있습니다.
