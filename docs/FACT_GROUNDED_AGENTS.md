# 주요 사실 근거를 검사하는 에이전트 구조

2026-10-13 합의: 댓글의 관점을 발견하는 과정과 그 관점이 사용하는 사실 근거를 검사하는 과정을 분리한다.
모든 댓글을 팩트체크하지 않는다. 에이전트 후보의 주요 사실 근거를 검사하고, 실제 답변 입력에는 지원 판정을 받은 사실만 넣는다.
원문에 없는 논거를 외부 자료에서 가져와 관점을 보강하거나, 거짓 전제를 고쳐 새로운 관점을 만들지 않는다.

현재는 **팩트 판정 인터페이스와 입력 조립 계약을 구현한 단계**다. 실제 자료 검색, 로컬 모델의 사실 판정 정확도,
자동 관점 생성 품질, 새 입력을 사용하는 답변·UI 연결은 완료되지 않았다. 기존 개발용 데모는 이 경로와 별개다.

## 분리된 처리 단계

```text
고정 댓글 snapshot → 후보 검색 → 공통 주장과 원문별 지지 관계
                                  ↓
                      사실·가치·예측 분류와 전제 의존성
                                  ↓
                      후보가 쓰는 주요 사실 주장 선택
                                  ↓
외부 문서 수집·동결 → 근거 구간 검색 → 로컬 사실 판정
                                  ↓
                     입력 조립과 제외·보류 사유 보존
                                  ↓
                  에이전트 답변 → 답변 검사 → 비교·원문 UI
```

팩트 판정부터 입력 조립까지 새 모듈로 분리했다. 위 전체 흐름이 자동으로 연결된 것은 아니다.
로컬 전용은 모델 추론을 뜻한다. 사실 근거는 향후 출처를 확인해 확보한 외부 문서를 로컬에 동결해 사용한다.
모델의 기억, 댓글의 반복, 댓글 수를 사실 검증 자료로 쓰지 않는다. 자료 수집 방식·출처 허용 목록은 아직 구현되지 않았다.

| 모듈 | 입력과 출력 | 현재 상태 |
|---|---|---|
| 기존 Factory | 원문 → 주장·후보·원문 관계 | 의미 오류가 남아 자동 품질 미승인 |
| 사실 근거 수집·검색 | 주요 사실 주장 → 문서·정확한 구간 | 미구현 |
| `factory/fact_checks.py` | 동결 주장·근거 → 인용을 포함한 판정 기록 | 로컬 호출 인터페이스·계약 테스트 구현; 실제 추론 미실행 |
| `agents/grounded_inputs.py` | 원문 관계·사실 판정 → 허용 입력·제외·보류 | 결정적 조립·재생 구현; upstream adapter 미구현 |
| 새 답변 경로 | 허용 입력 → 근거 제한 답변·검사 | 미연결; 기존 runtime은 새 상태를 거부 |

## 원문 지지와 사실 지원을 구분

원문 관계 검사는 “이 댓글이 이 주장을 말하는가”를 판단한다. 사실 검사는 “공급된 문서의 근거가 같은 대상·시점·조건의
이 주장을 뒷받침하는가”를 판단한다. 외부 문서가 맞는 말을 하더라도 댓글에서 지지하지 않은 주장은 추가하지 않는다.

공통 주장은 최소 3개의 서로 다른 canonical 댓글이 지지해야 입력 후보가 된다. 이는 개발 기준의 필요조건이며 의미 정확성이나
여론 대표성의 충분조건이 아니다. 공통 입장 지지 수와 각 이유의 지지 수를 따로 기록한다. 세 댓글이 입장에 동의하고 한 댓글만
특정 이유를 제시했다면 그 이유의 지지 수는 1이다. 사람이 세 명이라는 의미도 아니다.

사실 판정은 `supported`, `refuted`, `conflicting`, `insufficient`로 구분한다. 자료 없음·크기 예산 초과는
`unassessed`, 호출·응답 계약 실패는 `error`다. `supported`만 사실 입력 후보가 되며, 그 뜻은 **제공된 자료에 대한 모델의
잠정 지원 판정**이다. 포괄적인 진실 인증이나 독립 검증을 의미하지 않는다.

가치 판단과 예측은 사실로 인증하지 않고 해당 관점의 입장으로 표시한다. 잘못된 유형 분류로 사실을 가치로 숨기는 문제는
코드만으로 해결되지 않으며 별도 의미 평가가 필요하다.

## 입력 조립 정책

- 주장의 ID·내용·유형·대상·시점·조건·필수 사실 전제를 고정한다. 원문 관계는 주장 hash, 원문 hash, 정확한 인용 위치에 결합한다.
- 실제 입력에 들어가는 모든 사실은 원문 지지와 사실 지원 판정이 모두 필요하다. 외부 자료만 있는 사실은 넣지 않는다.
- 핵심 입장이 필수로 요구하는 사실 전제가 탈락하면 후보 전체를 보류한다. 전제를 지워 무조건적인 입장으로 바꾸지 않는다.
- 선택 가능한 이유는 해당 관점에 속한 댓글의 지지가 있어야 한다. 허용되지 않는 이유는 삭제 사실과 사유를 보존한다.
- 선언된 주요 사실이 모두 탈락하면 입장만 남겨 통과시키지 않는다. 사실 전제가 전혀 없는 가치 관점은 별도 표시된 입력 후보로만
  남기며, “검증된 사실 기반 agent”로 승격하지 않는다. 이러한 관점의 최종 UI·runtime 수용 정책은 후속 단계다.
- 전체 댓글과 탈락 주장은 인용 확인용 기록에만 남긴다. `prompt_input`은 허용된 주장·범위·유형·개별 지지 수만 반환한다.
- 입력을 내보낼 때 원래 bundle로 재조립해 결과 일치를 확인한다. 변경·만료된 원문·자료·판정·조립 결과는 재사용하지 않는다.

원문 관계 판정, 사실·가치 분류, 필수 전제와 주요 사실 목록은 아직 upstream 선언이다. hash와 `trace_id`는 그 판단의 정확성이나
실행 진위를 증명하지 않는다. 누락된 전제, 허위 지지 관계, 조작된 model metadata를 자동으로 발견하는 완성된 인증 체계가 아니다.
합성 자료도 개발 계약에서 허용하므로 이 출력에는 `quality_gate_passed=false`, `agents=[]`가 고정된다.
`fact_screened_input_not_runtime_approved` 상태는 기존 `AgentSession`이 받아들이지 않는다.

## 비용과 재사용 경계

사실 검사는 댓글마다 수행하지 않고 선택된 고유 주장에 대해 수행하는 구조를 목표로 한다. 재사용 판단에는 주장 전체, 대상·시점·조건,
근거 문서 전체 hash, 선택 구간, 모델·실행기 identity, 프롬프트·schema가 포함된다. 이번 구현은 저장된 판정의 일치 여부를 재검사한다.
영속 캐시 검색·스케줄러·중복 호출 제거는 아직 없다. 처리 속도가 개선됐다는 실측 주장도 하지 않는다.

한 판정은 최대 1회 호출·출력 500 tokens이며 자동 재시도·수정 호출은 없다. 직렬화된 요청이 30,000 bytes를 넘으면
자르지 않고 보류한다. 이 한도는 token/context 적합성을 보장하지 않으며 실제 모델 실험에서 별도로 확인해야 한다.
빈 근거에는 모델을 호출하지 않는다. 전체 서비스의 지연 시간이나 GPU 동시 처리 성능은 아직 측정하지 않았다.

## 모델 없이 실행하는 공개 예제

저장소 설치 후 가상환경에서 실행한다. 모델 서버, API 키, 실제 댓글이 필요하지 않다.

```bash
python -m experiments.grounding_contract_demo --output-dir runs/fact-grounding-demo
```

출력 폴더의 `overview.html`과 `summary.json`, 각 시나리오 JSON에서 원래 입력·판정 기록·조립 결과·모델에 전달할 입력을 비교한다.
기존 파일은 덮어쓰지 않으므로 재실행은 새 폴더를 지정한다. 모든 댓글·문서·판정은 직접 작성한 합성 자료다.

| 시나리오 | 입력 후보 수 | 확인한 동작 |
|---|---:|---|
| 지원 사실 1개와 반박 사실 1개 | 1 | 지원 사실만 남음; 입장 지지 3개와 이유 지지 1개 분리 |
| 모든 사실 미검사 | 0 | 주요 사실 근거 없음으로 보류 |
| 모든 주요 사실 반박 | 0 | 사실을 제거한 가치 입장으로 우회하지 않음 |
| 핵심 입장이 반박된 전제를 요구 | 0 | 의존성 때문에 전체 후보 보류 |
| 공통 입장 지지 댓글 2개 | 0 | 최소 지지 수 미달 |

2026-10-13 이 5개 예제를 실행했다. 네트워크 0회·모델 추론 0회·실제 생성 agent 0개다.
새 모듈의 34개 단위 테스트는 변경·만료·인용 오류·중복 지지·외부 이유 혼입·입력 우회 차단을 검사한다.
이는 프로그램의 계약 동작 확인이지 사실 판정·자동 clustering 정확도 실험이 아니다.

## 다음 순서와 남은 실험

1. **작은 사실 판정 실험:** 실제 댓글의 고정된 주요 주장과 같은 범위의 원문 자료로 입력·기대 판정·모델·코드·호출 예산을 먼저 동결한다.
   근거를 미리 제공하는 통제 조건에서 수치·대상·시점·인과·충돌·자료 부족을 검사한다. 평가용 assistant 판정은 독립 gold가 아니며
   runtime 수정 입력으로 쓰지 않는다. 기존 source-auditor의 실패한 4B prompt 반복과 다른 작업이다.
2. **자료 검색 실험:** 같은 주장에 자동 검색 자료를 제공해 통제 조건과 비교한다. 검색 누락과 근거 판정 오류, 오승인과 정상 손실,
   보류율·추론 시간·문서 확보 시간을 분리한다. 문서 URL·publisher 선언만으로 신뢰성을 승인하지 않는다.
3. **자동 Factory adapter:** 유형·범위·필수 전제·주요 사실 선택을 원문 및 실제 판정 trace와 연결한다. 기존 공통 주장/가입 품질 문제는
   별도로 남아 있다. 팩트체크를 추가했다고 원문 왜곡이 해결된 것으로 취급하지 않는다.
4. **답변과 UI:** 새 상태를 위한 독립 runtime을 연결하고, 전체 원문 재주입 없이 허용 입력만 사용한다. 질문별 근거 부족 시 보류하고
   댓글 인용·외부 사실 근거·제외된 이유·개별 지지 수를 구분해 표시한다. 이후 비교·후속 질문·원문 확인 흐름으로 실제 실행 검증한다.

각 실험의 채택 수치와 중단 기준은 실행 전에 확정한다. 입력 후보 0개를 의미 품질 성공으로 세지 않는다.
거짓 전제를 제거한 뒤 원래 관점의 대표성이 유지되는지도 별도로 평가해야 한다. 이 단계들이 남아 있으므로 자동 MVP 완료가 아니다.
