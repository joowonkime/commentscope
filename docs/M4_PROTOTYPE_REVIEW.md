## 강의에서 명시한 요구

PDF4쪽: 사용자에게 중요한 핵심 과업3개 이상을 지원하는 실제 작동 prototype을 만들고,
실시간 시연에서 성공을 보여야 한다. DPM3 피드백에 따라 과업을 수정할 수 있다.
multi-agent 설계는 선언한 목표를 안정적으로 달성하도록 반복 개선한다.
발표는 문제/해결/핵심 과업을 설명하고 시스템의 실제 동작을 시연한다. 제공 slide template은 없다.

Prototype Quality는 TA가 직접 사용해 평가한다. 세 기준은 사용자의 문제를 해결하는 전체 시나리오,
multi-agent pipeline의 품질과 일관성, 큰 사용성 문제의 부재다. 이 세 기준의 세부 배점은 slide에 없다.
PDF6쪽은 드물게 좋은 응답이 나오는 시스템과 반복해 좋은 응답이 나오는 시스템을 구별하고,
핵심 multi-agent 상호작용을 일찍 자주 시험하라고 강조한다. 예시의10/10은 별도 수치 합격선으로 제시되지 않았다.

## 구현 다음 순서에 주는 영향

1. 이번 M1 비교의 비용·오류·채택 보류를 기록하고 사례별 유료 수정 반복을 멈춘다.
2. 기존 실제 댓글→관점→Agent 경로를 같은 계약으로 완료할 수 있는 전체 비용/미완료 단계를 먼저 확정한다.
   생성된 모든 Agent의 근거·조건·runtime을 검토하며 좋은 Agent만 골라 전체 합격으로 보고하지 않는다.
3. 동일 자동 산출물을 제품에 연결해 신규 세션의 Explore→Converse→Reflect 전체 흐름을 반복 시험한다.
   총 시도/성공/부분 실패·의미 오류·대기시간·세션당 비용을 남긴다. 저장 응답 replay는 fresh 생성 성공과 구별한다.
4. TA용 사용 안내를 새 환경에서 따라 실행하고 사용자에게 핵심3과업을 수행하게 해 사용성 문제를 확인한다.
5. 검증한 버전/실행 방법/한계를 고정해 실제 시연·구현 설명·개인성찰과 맞춘다.

반복 횟수/허용 오류/추가 유료액은 이 slide에서 임의로 만들지 않는다. 후속 실험은 기존 예산/정식 gate와
별도 고정 평가 계획을 따른다. 이번 강의 확인만으로 새 유료 실행·전체999 실행·외부 공개를 시작하지 않는다.
