# 실제 영상으로 M4 팀 QA하기

## 공개 평가 서버

브라우저에서 **[Re.View 열기](https://35.212.169.73/mvp)**를 선택한다. 설치나 API 키 입력 없이 접속할 수 있다. 팀원과 평가자에게 같은 주소를 공유한다. AI 상호작용 기간은 **2026년 12월 14일 08:02 KST**까지이며 VM은 같은 날 08:05 KST 자동 중지 예정이다.

1. 첫 화면에서 준비된 영상 세 편 중 하나를 고르거나 그 영상의 YouTube URL을 붙여 넣는다. 첫 의견을 적고 Explore에서 관점과 출처를 연다. 새 영상의 댓글 수집과 Agent 생성은 운영자가 별도로 진행한다.
2. Converse에서 **New chat**을 열고 한 명에게 질문하거나 둘 이상을 선택해 자동 토론을 시작한다. 토론의 발언·결론을 읽고 비준된 합의가 있으면 합의 Agent에 질문한다.
3. Reflect에서 생각을 저장한 뒤 같은 브라우저의 Library에서 다시 연다. 평가 서버의 개인 세션은 생성 후 24시간 동안 유지된다.

운영자는 같은 고정 IP와 지속 디스크를 재사용한다. 재배포 시 기존 `runs/qa-server/`의 지출 기록과 세션을 보존한다. 서버 전체의 OpenRouter 추가 사용 한도는 21일 합산 $2다. Google Cloud의 프로젝트 예산 알림은 7,000원의 50%, 90%, 100%에 설정했다. 평가 기간이 끝난 뒤에도 주소를 예약하면 IPv4 비용이 계속 발생한다. [Google Cloud IP 요금](https://cloud.google.com/vpc/network-pricing)

## 같은 URL에 수정 반영하기

모델·데이터·지출 장부를 묶은 평가 계획은 시작할 때 기준 HTML·CSS·JS까지 해시로 고정한다. 11월 23일 그 세 파일을 직접 덮어썼을 때 화면은 열렸지만 기존 세션의 원댓글 조회가 HTTP 410으로 실패했다. 원본을 복구하고 운영 웹 서버에 공개 UI 전용 디렉터리를 만들어 같은 세션에서 HTTP 200과 원문 일치를 재확인했다.

1. UI 변경을 GitHub PR에 커밋하고 Node 회귀와 Linux Chrome 6개 화면 폭 검사를 실행한다. 기간 변경·서버 로직은 관련 Python 회귀와 양 OS CI로 확인한다.
2. 운영 프로젝트의 nginx는 [공개 사이트 설정](../deploy/nginx/commentscope.conf.in)을 사용한다. `/mvp`의 HTML·CSS·JS와 검토된 표본 집계 JSON은 `/srv/commentscope-ui/current`에서 읽고, API와 기존 이미지 경로는 원래 Python 서비스로 보낸다. 인증서와 비밀 설정은 서버에 보관한다.
3. 운영자는 아래 명령으로 커밋의 공개 파일과 SHA256 목록을 묶어 비공개 관리 경로로 전송한다. 호스트에서 같은 스크립트의 `activate`를 실행하면 파일을 검증한 뒤 공개 버전을 원자적으로 전환한다. 이전 버전도 같은 명령으로 다시 선택할 수 있다. 운영자의 로컬 명령과 VM 명령은 다음과 같다.

```sh
python3 deploy/assessment_ui.py package <commit> /tmp/commentscope-ui-release
# VM에 패키지와 스크립트를 전송한 후 VM에서 실행
sudo python3 assessment_ui.py activate /path/to/commentscope-ui-release
```

4. 외부에서 기존 QA 세션으로 아래 검사를 실행한다. 공개 파일의 해시, 등록 목록, 세션, 실제 원댓글 본문까지 읽는다. 이 검사에 모델 비용은 없다. `qa-browser-state.json`은 운영자 전용 QA 브라우저의 Playwright storageState다. 이 파일은 비공개 디렉터리에만 보관한다.
5. 변경된 과업을 같은 URL에서 다시 조작하고, 유료 기능을 확인했다면 운영 장부에서 확정 청구와 미결 건을 대조한다. 실패가 남으면 직전 공개 UI를 다시 활성화해 같은 검사를 수행한다.

```sh
python3 deploy/assessment_ui.py verify https://35.212.169.73 /tmp/commentscope-ui-release /private/qa-browser-state.json
```

## 운영자가 로컬에서 재현할 때

팀원과 평가자는 위의 공개 주소에서 QA를 진행한다. 로컬 재현이 필요한 운영자는 Python 3.12 이상을 준비하고, 배포한 버전의 Git checkout에 비공개 분석 입력 `runs/qa-inputs/`를 복원한다. 프로젝트 루트에서 다음 명령으로 준비된 세 영상을 검사한다.

```powershell
py -3 tools/launch_mvp.py --check
```

실제 대화까지 재현하려면 운영 환경에 `OPENROUTER_API_KEY`를 설정하고 `py -3 tools/launch_mvp.py --max-usd 1`을 실행한다. macOS와 Linux에서는 `python3`을 쓴다. 세 관점의 자동 토론에는 약 1.075달러의 예약 여유가 필요해 로컬 최초 실행 한도로 `--max-usd 1.25`를 사용할 수 있다. 실행할 때 출력되는 주소의 `/mvp`를 연다. 이전 로컬 세션의 기록은 세션 유효 기간에 같은 서버 폴더·주소·브라우저에서 다시 연다. 준비된 영상의 재열람에는 YouTube 키가 필요하지 않다.

| 공개 서버의 등록 영상 | 재현할 수 있는 범위 |
| --- | --- |
| 스브스뉴스, 4.5일제 | 기본 영상이자 로우파이의 원래 영상. 댓글·답글 751개를 수집해 고유 댓글 750개를 처리했다. 최종 입장에 연결된 댓글은 15개다. Agent 11개 중 3개는 원문에 이유가 있고 일부는 비슷한 입장을 담고 있다. [영상](https://www.youtube.com/watch?v=BAHKmi4F1L8) |
| Jubilee, AI와 교육 | Library 또는 영상 URL로 연다. 처리 댓글 180개, 관점 2개. 도구를 사용하는 사람의 책임과 AI 감지기의 신뢰도를 다룬다. [영상](https://www.youtube.com/watch?v=7AGa5z69zqU) |
| CNBC, 주 4일 근무 | Library 또는 영상 URL로 연다. 처리 댓글 96개, 관점 4개. 고유 댓글 4개가 입장에 연결되며 네 관점 모두 짧은 근무를 지지한다. [영상](https://www.youtube.com/watch?v=RrFaNO3rTaA) |

새 영상은 운영자가 YouTube Data API 키로 수집한다. 프로젝트를 설치한 환경에서 `python -m commentscope collect-youtube "YOUTUBE_URL" --output data/new-video.json --max-comments 180`을 실행한다. GitHub 브랜치에서는 확대 검색 계약의 3,000개 상한을 준비·재검사·제품 등록에 적용한다. 이번 SBS Factory 실행은 실제 955회 호출에 $3.466732292를 썼다. 저장 분석을 불러올 때 이 비용은 다시 들지 않는다. 3,000개 영상의 실제 비용과 관점 품질은 아직 측정하지 않았다. 수집 후 운영자가 Factory에서 원문 대조를 통과한 Agent를 등록하면 모든 사용자가 Library와 URL로 열 수 있다. 미등록 URL을 입력하면 화면에 안내가 뜨고 작성 중인 의견과 기존 영상이 유지된다.

## 월요일에 바로 확인할 SBS 경로

Figma의 원래 장면과 동일한 영상을 기본값으로 등록했다. Before Use의 재생 버튼 또는 **Watch on YouTube**로 본편을 연다. 영상의 썸네일과 Figma에 캡처된 장면은 재생 시점에 따라 다르다. 실제 기기의 화면 폭에 맞는지도 확인한다. [Figma 원본 화면](https://www.figma.com/design/Q5oqIs2ekQIagiboAFX7Qc/MAS?node-id=333-6991)

| 과업 | 재현 예시와 확인한 결과 |
| --- | --- |
| Explore | 9시 출근·5시 퇴근에 찬성한다는 의견을 작성하고 **9시~5시 근무제 도입 제안**과 비교한다. 실제 비교에서 공통점 배지와 양쪽 문장의 같은 녹색 강조를 확인했다. 첫 화면은 11개 관점에 연결된 고유 댓글 15/750(2.0%)을 표시한다. 댓글 좋아요 총합 17,534개 중 이 댓글들이 받은 좋아요는 1,453개다. 서로 다른 관점에 중복으로 합산하지 않는다. |
| Converse | **New chat**에서 **9시~5시 근무제 도입 제안**, **오후 4시 퇴근 제안**을 골라 **Group conversation**을 연다. 두 관점의 퇴근 시각을 물어 네 번의 발언을 확인했다. **Send question to**에서 9시~5시 관점을 골라 출근 시간을 바꾸려는 이유를 물었을 때 이 Agent만 답했고 원댓글을 열 수 있었다. |
| Reflect | **Choose individual messages**를 펼쳐 발언을 고르고 현재 생각을 적어 **Analyze**를 누른다. 실제 제안에서 유지된 의견과 더 생각할 점을 확인했다. 문구를 직접 고쳐 저장한 뒤 새로고침해도 같은 저장본을 열 수 있었다. |
| 자동 토론 | SBS에서 검증 보류로 마친 실제 시험과 CNBC에서 합의 Agent를 만든 실제 시험이 각각 있다. 합의 없이 끝난 경우 **Ask these perspectives in a new chat**으로 기존 참여자를 고른 일반 대화를 열 수 있다. |

로컬 그룹 QA에서는 위의 기본 `$1` 실행 명령을 사용했다. 생성 전에 답변과 검증에 필요한 최대 비용을 함께 확인하므로 `$0.30` 시험에서는 두 사람의 첫 답변이 시작되기 전에 한도에 걸렸다. 실행 창의 상한과 실제 청구액은 별도로 확인한다.

외부 AI가 일시적으로 실패해 과금 확인이 보류되면 운영자가 서버를 `Ctrl+C`로 정지하고 같은 폴더에서 `py -3 tools/review_product_http.py`를 실행한다. 확정된 일시 HTTP 오류와 완료 영수증을 대조할 수 있으면 원래 최대 예약액을 전액 보수적으로 계상한 뒤 같은 실행 명령으로 서버를 다시 시작한다. 참가자는 다른 질문을 제출할 수 있다. 다른 종류의 중단에는 이 명령이 사유를 출력하며 장부를 보존한다. 원댓글 보기와 직접 성찰 작성은 AI가 중단된 중에도 가능하다.

## 조원이 직접 확인할 흐름

1. 오른쪽 위에서 **한국어** 또는 **English**를 선택하고 초기 의견을 적은 뒤 Explore로 들어간다. **논점별 관점 탐색**에서 논점을 펼쳐 원문 근거를 열고 참가자를 고른다. SBS는 11개 관점을 4개 논점(5·3·2·1개), CNBC는 4개 관점을 2개 논점(3·1개)으로 표시한다. Jubilee의 서로 다른 두 관점은 바로 선택할 수 있다. **관점별 지지율·좋아요 비교**를 누르면 표본 지지 댓글 수·비율과 연결된 좋아요 비중을 개별 관점별로 확인할 수 있다. **Rank by → Likes**를 눌러 순위를 바꾼다. SBS의 ‘주 5일 유지·하루 근무시간 단축’은 표본 입장 댓글 34개에서 지지 0개이고 이 관점에만 연결된 댓글은 좋아요 1,199개를 받았다. 이는 연결된 좋아요 1,453개의 82.5%다. 공통 행의 좋아요 1개도 분모에 한 번 포함한다. 표 위의 연결률은 전체 17,534개 중 1,453개(8.3%)이고, 두 열은 0~100% 눈금을 쓴다. **Coverage and counting method**에는 표본 검토 방식과 전체(100%) 비율선이 있다. SBS 입장 댓글 34개 중 단일 지지 5개, 복수 지지 7개, 어느 관점도 지지하지 않은 입장 22개다. 관점 카드에서는 대화할 참가자를 선택하고 **Source comments**로 직접 근거 원문을 연다.
2. 초기 의견이 있으면 Explore가 자동으로 비교를 접수한다. **perspectives compared**의 완료 수와 각 카드의 대기·비교 중·완료 표시를 확인한다. 카드 본문이나 **Compare with my view**를 눌러 색과 글자로 표시된 관계를 양쪽 문장에서 찾는다. 같은 초기 의견으로 새로고침하면 완료한 비교를 재사용한다. 다른 단계로 이동하면 남은 미접수 카드는 Explore로 돌아올 때 이어진다. 일시적으로 실패한 카드에는 재시도 안내가 나온다.
3. Converse의 **New chat**에서 참여자를 고른다. 한 명이면 1:1, 여러 명이면 그룹 대화 또는 자동 토론을 선택할 수 있다. 그룹 대화에서 한 명을 지정해 후속 질문을 보낸다.
4. 검증 보류가 나오면 등록된 원댓글을 확인한다. 일반 대화가 오류로 멈추면 **Ask another question**으로 입력창을 다시 연다. 이전 발언과 지출이 유지된다.
5. 자동 토론의 참여자별 발언과 결론을 읽는다. 실제로 검증·비준을 통과한 합의가 생기면 합의 Agent를 열고 질문한다. 근거가 부족하면 결론에서 어느 단계까지 진행됐는지 확인한다. Reflect에서 직접 작성하거나 제안을 검토해 저장하고 Library에서 다시 연다.


### 팀 사용성 점검

- SBS에서 ‘하루 근무시간과 퇴근 시각’을 펼쳐 4시와 5시 퇴근 주장의 차이를 원댓글로 설명해 본다. 첫 참가자를 고르고 논점을 접은 뒤, ‘포괄임금제’에서 두 번째 참가자를 골라 토론 참가자 이름을 확인한다. 논점 옆 숫자를 댓글 수나 찬성률로 읽었는지도 기록한다. 전달본의 ‘내 의견과 비슷한 순’과 ‘새로 생각할 점’ 정렬이 필요한 상황이 있었는지도 함께 본다.
- Converse에서 한 사람을 지정해 질문하고 그 답의 원문을 다시 찾는다. 전달본의 근거 저장, 응답이 실패한 참가자만 다시 시도하는 동작이 현재 흐름에서 언제 필요했는지 적는다.
- Reflect에서 AI의 해석과 연결된 발언을 열고, 동의하지 않는 해석을 고쳐 저장한다. 전달본은 항목 옆에 동의·수정·거절 버튼을 둔다. 공개 화면에서는 제안 선택과 수정 위치를 처음 보는 사람도 찾을 수 있는지 확인한다. 팀에 남길 내용은 영상, 시도한 행동, 기대한 결과와 실제 결과다.

### 다른 등록 영상의 관점 비율 검토

1. 관점 근거의 수와 별개로, 검토할 쟁점을 먼저 문장으로 정한다. 해당 환경의 Factory 계획이 참조하는 스냅샷 경로를 읽을 수 있는 위치에서 아래 명령을 실행한다. 워크시트에는 원댓글과 부모 문맥이 들어가므로 비공개 경로에 보관한다.

   ```sh
   python tools/opinion_sample.py draw runs/VIDEO "Which policy should change?" /private/review.json
   python tools/opinion_sample.py summarize runs/VIDEO /private/review.json --reviewer ai
   ```

2. 두 명령 사이에 워크시트의 각 댓글을 읽고 `classification`을 `position`(쟁점에 대한 자기 입장), `no_position`(다른 주제·무입장), `unclear`(귀속·빈정거림·문맥 등으로 판단 곤란) 중 하나로 기록한다. 쟁점에 대한 지지·반대·조건·대안·구체적 우려는 입장에 포함한다. `supports`에는 해당 작성자의 의견이 실제로 뒷받침하는 등록 입장 ID를 적는다. 다른 사람의 말이나 특정 조건을 무시해야 성립하는 지지는 제외한다. 동의하는 카드가 없어도 입장 댓글은 분모에 포함한다.
3. 추출은 처리한 고유 댓글 ID 전체를 고정 시드와 영상 ID로 해시 정렬해 처음 50개를 쓴다(50개 이하면 전수). 순서·좋아요·Agent 근거 선정 여부를 추출에 쓰지 않는다. 직접 근거였던 댓글도 같은 확률로 뽑힐 수 있다. 분자·분모는 같은 표본에서 센다. 원래 영상에서 수집한 댓글 집합과 판독 방식의 한계가 있다.
4. `summarize` 출력에서 `analysis_id`를 키로, 나머지 필드를 값으로 `src/commentscope/product/opinion-samples.json`에 등록한다. 공개 파일에는 집계만 둔다. 분석 ID는 Factory 계획·스냅샷·산출물에 결합되어 있다. 표본이 없거나 버전이 달라지면 제품은 비율 없이 직접 근거를 보여준다. 비율 등록과 화면 재열람에는 모델 호출이 없다.


### 새 등록 영상의 관점 번역

한영 화면은 같은 분석에 준비한 관점 이름·주장·이유·조건·쟁점 번역을 재사용한다. 직접 작성한 의견과 실제 출처 댓글은 원문으로 열린다. 신규 영상에서는 Factory 실행 폴더로 작업지를 만들고 각 `translation`을 반대 언어로 작성한다. 이름은 짧게 유지하고, 주장과 이유의 조건·확신 정도·대상은 원문과 대조한다. 같은 분석에 대해 다음 명령을 실행한다.

```sh
python tools/perspective_translations.py draw runs/VIDEO ko > /private/views.json
python tools/perspective_translations.py publish runs/VIDEO /private/views.json > /private/published-views.json
```

영어 원문의 경우 첫 명령의 `ko` 대신 `en`을 사용한다. 원문 언어가 섞인 영상은 해당 작업지 필드에 개별 `source_language`를 지정할 수 있다. 두 번째 명령의 출력 객체를 `src/commentscope/product/perspective-translations.json`에 분석 ID별로 합친 뒤 UI와 함께 배포한다. 공개 항목은 번역과 원문 해시를 담는다. 분석·필드·원문이 일치하는 번역만 적용되며, 카드가 달라졌거나 번역이 아직 없는 문장은 원문으로 표시한다.

작업지의 선택 항목 `topics`에는 중립적인 `ko`·`en` 논점명과 그 논점에 속하는 개별 관점 ID 배열 `members`를 기록할 수 있다. 같은 관점을 두 곳에 넣을 수 없다. 공개하기 전 두 언어의 제목이 구성원의 찬반·조건을 단정하지 않는지 확인한다. 묶음을 준비하지 않은 영상이나 묶음 밖 관점도 원래 카드로 열 수 있다.

## 개발과 운영의 역할

| 계층 | 구현과 책임 |
| --- | --- |
| 수집과 Agent 생성 | YouTube 수집 → 스냅샷 → Factory 후보 발굴·근거 판정 → Agent 입력 컴파일. 게시 가능한 관점 결정은 이 계층이 담당한다. 새 영상 시험에는 `tools/prepared_video_trial.py prepare --max-new-usd`로 그 실행의 추가 지출 상한을 지정할 수 있다. |
| 분석 표시 | `src/commentscope/product/analysis.py`가 등록 프로필을 카드로 변환한다. 원댓글 ID로 범위와 좋아요를 집계한다. 선택적인 `perspective-names.json`은 실제 등록 ID에 짧은 이름을 연결한다. |
| 대화와 상태 | `product/app.py`는 세션·질문·비교·성찰을 저장한다. `product/debate_service.py`와 `agents/structured_debate_runtime.py`가 자동 발언과 결론을, `agents/synthesis_agent.py`가 비준된 합의의 컴파일을 담당한다. |
| 화면 | `product/mvp.html`, `mvp.js`, `mvp.css`가 같은 호스트의 `/api/v1`을 사용한다. QA 기준은 기존 Figma 문서에 기록했다. [Figma 명세](https://www.figma.com/design/Q5oqIs2ekQIagiboAFX7Qc/MAS?node-id=823-3498) |
| 모델과 운영 | 생성과 검증은 기존 OpenRouter 브로커와 장부를 통과한다. `tools/launch_mvp.py`는 서버를 시작하고 운영자가 지정한 종료 시각과 추가 지출 한도를 고정한다. |

## 채점 기간에 접속할 URL 운영

공개 호스트에 Python 3.12 이상과 지속 디스크를 준비한다. 운영 백업의 `runs/qa-inputs/`를 같은 버전의 서버 코드 아래에 복원한다. 기본 영상은 `catalog.json`의 첫 항목이다. 같은 사용자로 같은 절대 경로에서 실행하고 재시작 시 `runs/qa-server/` 전체를 재사용한다. 여기에 세션 SQLite, 권한 바인딩, 이전 지출과 호출 영수증이 저장된다. 채점 중에는 고정한 코드와 자료 버전을 사용한다.

1. 운영 서비스의 환경 변수에 팀용 `OPENROUTER_API_KEY`를 설정한다. 팀원이 브라우저를 열 때는 개인 키를 입력할 필요가 없다. 기존 분석만 제공하는 서버는 YouTube 키 없이 실행된다.
2. 운영자의 실제 HTTPS 호스트와 종료시각을 넣어 아래 명령을 실행한다. 평가용 창은 최초 시작부터 최대 21일이고 등록 근거 만료 전에 끝나야 한다. 명시한 총액은 이 기간 전체에 적용되며 최대 2달러다. 예산이 소진되면 새 AI 호출이 멈춘다. 실행 중인 서버에서 기존 기록 읽기와 수동 성찰 저장은 각 세션 유효기간 안에 가능하다.

```sh
python3 tools/launch_mvp.py --check
python3 tools/launch_mvp.py --port 8080 --public-origin "https://YOUR_HOST" \
  --evaluation-until "YYYY-MM-DDT23:59:00+09:00" --max-usd 2
```

3. 서비스 관리자가 같은 명령을 재시작하도록 설정하고 HTTPS 프록시가 같은 VM의 `127.0.0.1:8080`으로 원래 Host를 전달하게 한다. 사이트의 `/mvp`, `/mvp/*`, `/api/v1/*`만 전달한다. 아래는 Caddy에서 사용할 구성이다.

```caddyfile
YOUR_HOST {
    @product path /mvp /mvp/* /api/v1/*
    handle @product {
        reverse_proxy 127.0.0.1:8080
    }
    handle {
        redir / /mvp
        respond 404
    }
}
```

4. 다른 네트워크의 새 브라우저에서 가입이나 설치 없이 의견 저장, 원문, 실제 응답, 토론 결론, 성찰 저장을 확인한다. 서버 재시작 뒤 같은 브라우저에서 기록을 다시 연다. 이 검증을 끝낸 HTTPS 주소를 M4 PDF의 **Live evaluation URL**에 넣는다. 소스 저장소 링크는 별도 제출 항목이다.
