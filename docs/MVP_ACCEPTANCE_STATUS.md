# 시연 MVP의 구현과 검증 상태

현재 자동 MVP는 완료되지 않았다. 고정40건의 로컬 NLI 사실 판정과 합성 관점의 선택형 답변은 개발 기준을 통과했다.
코드 테스트 통과, 통제된 부품 평가, 실제 댓글에서 생성한 에이전트의 품질은 서로 다른 완료 조건이다.

## 합의 기준과 현재 증거

| 항목 | 합의 기준 | 현재 확인한 상태 |
|---|---|---|
| 시연 입력 | 영상1개, 댓글 최대1000개 | 기존 공식 API snapshot1000개, canonical999개 유지 |
| 실제 agent | 서로 다른 agent2개 이상, 각각 canonical 지지3개 이상 | 새 경로에서 승인한 실제 agent0개 |
| 원문 충실성 | 고정100관계 승인 정밀도95% 이상, 정상 지지 보존80% 이상 | 이번 기준의100관계 평가는 미실행; 기존 의미 오류 미해결 |
| 주요 사실 | 지원·반박·충돌·자료 부족 각10건, 비지원 오승인0, 지원8/10 이상 | 8B 단독 미달; 같은40건 NLI 지원9/10·오승인0/30·오류0으로 개발 기준 통과 |
| 답변 | 답변 가능·보류 대상 각각90% 이상 | 합성 관점의 실제 모델 선택에서 각각20/20; 실제 agent 평가는 미실행 |
| 응답 속도 | 준비된2-agent 비교20회 P95≤60초 | 합성 관점2개 비교20회 P95 10.27초; 실제 agent 지연은 미측정 |
| 전체 분석 시간 | 첫 분석 최대1시간 | 새 end-to-end 경로 미연결, 미측정 |
| 추론 예산 | 새 사이클 누적8시간 | SQLite ledger로 실패·미완료 예약 포함 계측, 한도 초과 호출 차단 |

## 실제 문서 기반 사실 판정

이미 확보한 Kela 공개 문서의 본문을 재사용했다. 추가 검색·새 모델 다운로드·유료 API는 사용하지 않았다.
개발8건에서 기존4B는 기대 일치5/8, 캐시된8B는7/8이었다. 두 모델 모두8건 전부 일치라는 사전 점검 기준에는 미달했다.
8B의 정상 지원 보존과 계약 오류가 개선되어, 같은 모델에 더 넓은 고정40건 진단을 수행했다. 사전 실패를 합격으로 바꾸지 않았다.

40건은 실제 Kela 문서에 대한30주장과 명시적인 합성 충돌10사례다. 모든 기대 판정은 실행 전에 작성한 assistant 개발 참조이며,
실제 댓글에서 자동 추출한 사실도, 독립 연구자 gold도 아니다. 실제 자료의 출처 충돌을 충분히 검증한 결과로 해석하지 않는다.

| 기대 판정 | 8B의 판정 | 정확히 일치 |
|---|---|---:|
| 지원10 | 지원10 | 10/10 |
| 반박10 | 반박10 | 10/10 |
| 충돌10 | 충돌5, 반박5 | 5/10 |
| 자료 부족10 | 자료 부족9, 지원1 | 9/10 |

오승인은 본문의 실험 참여자 수를 대조군 인원수로 옮긴 경우다. 충돌에서는 두 문서 중 반박하는 문서만 따라간 오류가 있었다.
40회 호출 경과 합은401.32초다. 서버 시작·수집·전체 댓글 분석 시간이 아니므로 영상 분석 속도로 보고하지 않는다.
같은 문서를 개별 entailment 판정기로 검사하고 두 모델이 일치할 때만 채택하는 비교도 완료했다.
기존 로컬 DeBERTa와 고정0.8 threshold를 사용했고 정상 지지 손실을 같은 분모로 평가했다.

| 구성 | 지원 보존 | 비지원 오승인 | 충돌 정확 분류 | 결과 |
|---|---:|---:|---:|---|
| NLI 단독 | 9/10 | 0/30 | 10/10 | 개발 기준 통과 |
| 8B와 NLI 일치 | 9/10 | 0/30 | 5/10 | 지원 수용 기준 통과; 충돌5건을 자료 부족으로 보류 |

NLI 단독은 총38/40 기대와 일치했다. 첫해 고용 효과의 지원·반박 각1건을 자료 부족으로 보류했다.
110개 passage-claim forward를 CPU에서 모델 로딩 포함25.29초에 수행했다.8B 호출 합401.32초와 측정 범위가 다르므로
순수 모델 속도 배율이나 전체 영상 처리 속도로 일반화하지 않는다. NLI는 영어 문장만 검사하고 메타데이터·scope 필드를 별도로 추론하지 않는다.
현재 증거에서는 NLI 단독을 다음 사실 판정 통합 후보로 선택한다. LLM을 중첩해도 오승인 이득은 없고 충돌 구분만 손실됐다.
실제 corpus에서의 적용, 기록 adapter, 자료 검색과의 연결은 남아 있다. 두 모델을 함께 썼다는 이유로 독립 검증이라고 부르지 않는다.

## 답변을 제한하는 새 구현

`agents/grounded_runtime.py`는 허용 주장 ID만 선택하게 한다. 실제 공개할 문장·범위·지지 수·댓글 인용·외부 근거는 host가
입력 조립 결과에서 가져온다. 필수 사실 전제도 별도 표시하므로 답변에서 전제를 숨길 수 없다.
원문 전체와 탈락 사실은 모델 입력에 넣지 않는다. 질문은 기존 주장을 선택할 근거이지 새로운 사실의 출처가 아니다.

이 경로는 자유로운 재서술·번역·새 논거 생성을 하지 않는다. 원문 기반의 고정 주장으로 응답하는 개발 방식이며,
질문 관련성·답변 가능성 선택과 upstream의 주장 정확성은 여전히 모델 평가가 필요하다.
기존 `AgentSession`과 UI의 기본값을 바꾸지 않았고 실제 자동 생성 agent를 승인하지 않았다.

첫0.1 실행에서는 답변 가능14/20, 올바른 보류0/20이었다. 스키마가 모순된 상태 조합을 허용했고 핵심/이유 역할도 입력에 없었다.
0.2는 answerability별 JSON 분기로 출력 조합을 제한하고 upstream이 선언한 core/reason/prerequisite 역할을 명시했다.
같은20질문×2관점 재실행에서 답변20/20·보류20/20·계약 오류0, 비교 P95 10.27초를 확인했다.
표본·기대값·평가 기준을 바꾸지 않았지만 알려진 개발 질문 재시험이므로 일반 질문 성능을 보장하지 않는다.
원문에 없는 인용을 생성할 수 없는 구조와, 실제 upstream 주장이 충실하다는 증명도 구분한다.

## 재현과 보존

- 새 실험의 순서는 prepare → run → verify다. prepare 후 기대값·입력·코드·모델·예산을 동결하며 기존 실행 폴더를 덮어쓰지 않는다.
- `experiments.fact_evidence_probe`: 실제 공개 문서 개발8건.
- `experiments.fact_deployment_probe`: 동일8건의 캐시된8B 배포 비교.
- `experiments.fact_gate_probe`:30개 실제 문서 사례와10개 합성 충돌 사례의40건 진단.
- `experiments.fact_nli_probe`: 같은40건의 로컬 NLI 및 합의 판정 비교. 로컬 ML 가상환경을 사용한다.
- `experiments.grounded_answer_probe`: 합성 관점2개에 실제 모델이20질문씩 선택하는 부품 평가. 실제 agent 생성 결과가 아니다.
- `experiments.mvp_probe_report`: 완료 manifest의 hash를 검사하고 private 결과 HTML을 렌더링한다. 새 모델 호출은 없다.

이 실험들은 private plan/model/corpus에 의존하며 새 clone에서 바로 재현되는 공개 예제가 아니다.
원문·모델 출력·평가 참조·예산 DB는 Git에서 제외한다. 공개 모델 없는 예제는 기존 `experiments.grounding_contract_demo`다.
실험 코드 변경 후 과거 실행을 재생하려면 당시 코드 revision이 필요하다. 현재 파일 hash가 다르면 검증은 의도적으로 거부한다.
40건 NLI 비교와 답변0.1의 코드 체크포인트는 `67062df`다. 답변0.2 변경 전 각 verify를 실제 실행했다.
통합 결과 화면은 private `runs/mvp-agreed-20261013/overview.html`이며 원문·모델 출력과 함께 공개 Git에서 제외한다.

다음 연결 순서는 사실 판정의 채택 여부 결정 → 자동 Factory adapter와 고정100관계 평가 → 실제 agent 핵심·근거 전수검토 →
새 답변 UI와 실제20회 응답·전체1시간 측정이다. 부품 성능만으로 이 순서를 완료했다고 보고하지 않는다.
