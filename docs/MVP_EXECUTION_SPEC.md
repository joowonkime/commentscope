## 2. 선택한 처리 구조

```text
Source Registry + 원문 검색 임베딩
 → 원문 묶음별 최소 주장 추출
 → 추천 출처의 실제 지지 확인
 → 동치 후보 병합 + 원문별 후보 검색
 → 원문-최종 주장 관계 판정 + 고유 지지 집계
 → 지지≥3 후보의 출처별 상세 논거 추출·검증
 → 고정 외부 증거 자료와 주요 사실 대조
 → Agent compiler → 기존 runtime → 오프라인 평가
```

실패했던 `target/statement/entity/time/conditions` 동시 생성기를 그대로 채택하지 않는다.
처음에는 **각 원문의 최소 명제**만 뽑고, 동치 명제를 모아 공통 입장을 만든다.
개인적 이유를 공통 입장 가입 조건으로 바꾸지 않는다. 필수 조건은 최소 명제에도 남긴다.
전체999개에 상세 논거 frame을 선행 생성하지 않고 충분한 지지가 모인 후보부터 상세 분석한다.

### 2.1 원문과 최소 주장

원문 registry는 전체 원문·canonical ID·중복 관계·부모 문맥·원문 hash를 보존한다.
부모는 명시적 지시/동의를 해석하는 문맥이지 답글 작성자의 이유를 가져오는 출처가 아니다.
segment는 코드가 생성하고 모델은 ID만 선택한다. 인용문은 코드가 원문에서 복원한다.

기존 MiniLM으로 전체 원문 임베딩을 CPU에서 한 번 계산하고 모델을 내린다.
미배정 ID 중 가장 작은 ID를 seed로 하여 cosine 근접7개를 더한다. 동점은 ID순, 최대8원문이다.
유사도 임계값으로 원문을 탈락시키지 않는다. 긴 입력은 context 검사 후 묶음을 분할한다.

출력은 원문별 `covered/partial/non_substantive/unresolved`와 최소 명제 목록이다.
명제는 완결된 입장·대상·필수 시점/조건을 포함하는 최대600자 문장과 원문 segment ID로 표현한다.
별도 자유 생성 이유·entity·time 필드는 요구하지 않는다. 600자를 넘는 의미는 자르지 않고 용량 보류한다.
최대16명제/묶음이며, 용량 partial 원문은 이미 추출한 명제를 제공해 **추가 추출1회**만 허용한다.
이후 partial은 그대로 보고한다. 실패 응답 재시도나 JSON 복구가 아니다.
non_substantive 판정도 검색 대상이나 고정 평가 분모에서 원문을 삭제하는 근거가 되지 않는다.

원문→명제 추천은 독립적인 원문 관계 판정을 통과해야 지지로 사용할 수 있다.
추천 지지가0개인 후보는 미확인으로 보존하되 동치 병합·Agent 승격의 근거로 사용하지 않는다.

### 2.2 후보 정리와 병합

명제 text는 Unicode NFC·공백만 정규화한다. 부정·조건·시점·구두점을 임의 제거하지 않는다.
후보 ID는 정규화 문구와 계약 버전의 SHA256으로 만들고, 추출 레코드는 source hash를 추가해 출처별로 구분한다.
동일 정규화 문장은 중복 제거하고 출처 목록을 합친다. 추천 수는 지지 수가 아니다.
나머지는 후보 임베딩을 CPU에서 계산한 후 후보당 가까운3후보를 의미 비교 대상으로 삼는다.
중복 없는 무방향 쌍을 ID순으로 검사하며, 후보의 실제 지지 원문을 함께 제공한다.
비교용 원문은 후보당 ID순 최대3개로 고정한다. 이는 의미 해석용 문맥이지 전체 지지의 대리 승인 표본이 아니다.

관계는 `equivalent/a_narrower/b_narrower/opposed/different/uncertain`다. **equivalent만 병합**한다.
ID순 greedy complete-link를 사용한다. 두 집합의 모든 교차 쌍이 실제 equivalent일 때만 합친다.
미검사 쌍이 있으면 병합하지 않는다. A≈B·B≈C만으로 A≈C를 간주하지 않는다.
조건부·반대 주장은 별도 후보로 유지한다. 더 넓은 새 주장을 생성해 병합하지 않는다.
최종 문구는 집합 내 가장 작은 안정 ID의 기존 명제를 선택한다. aliases·판정·미검사 관계를 보존한다.
병합 후에는 **최종 문구와 원문**으로 지지를 확인한다. 다른 문구의 지지 수를 그대로 합산하지 않는다.

### 2.3 검색과 원문 지지 판정

각 원문은 가까운 최종 후보3개와 모든 추출 추천 후보를 판정한다.
supported/conditional 연결이 없거나 추출 상태가 partial/unresolved이면 다음3후보를 추가 판정한다.
확장1회로 끝내며 전체 모든 쌍을 검사하지 않는다. 미검사 쌍은 unassessed다.
같은 원문 hash·후보 문구 hash·schema/prompt/model 설정의 완료 판정만 재사용한다.

최대8쌍/호출로 입력을 공유하되 각 쌍은 독립 판정한다. 입력은 전체 원문과 부모 문맥이다.
`supported/conditional/opposed/unrelated/uncertain`, 작성자 귀속, 범위 일치, 원문 segment ID를 받는다.
조건부 원문은 무조건 주장에 표를 주지 않는다. 조건을 포함한 별도 후보와 일치하면 그 후보의 supported가 될 수 있다.
타인의 말·질문·불확실한 추측을 작성자의 확정 입장으로 바꾸지 않는다. 귀속·범위 불확실은 집계에서 보류한다.
누락/중복/알 수 없는 ID와 형식 오류는 해당 응답 묶음 전체를 실패 처리하고 원문·후보는 보존한다.

Support Ledger는 후보당 canonical 원문1표, 전체 활용률에서는 원문1개로 집계한다.
지지≥3은 상세 분석·승격의 필요조건이며 신뢰성의 자동 증명이 아니다.
표시 지지 수는 **이 snapshot·실제로 판정한 쌍에서 확인된 수**다. 영상 전체 사람 수나 여론 비율이 아니다.
한 원문이 여러 후보를 지지할 수 있으므로 관점별 지지 합이 전체 원문 수를 넘을 수 있다.

### 2.4 상세 논거와 Agent 구성

지지≥3인 모든 후보와 그 후보의 모든 집계 지지 원문을 상세 분석한다. 좋은 사례 몇 개만 골라 만들지 않는다.
최대4원문/호출로 묶고 원문 hash와 분석 계약이 같으면 여러 후보에서 재사용한다.
명제와 연결된 이유·가치·경험적 주장·예측·필수 조건·필수 사실 전제·처리 완전성을 기록한다.
최대16논거 단위/묶음, 용량 partial 추가 추출1회, 이후 미해결은 명시한다.
논거는 별도 원문 대조로 검증한다(최대8쌍/호출). 자기 검사를 독립 gold로 부르지 않는다.
이유·조건을 어떤 후보에 연결하는지도 판정 대상이다. 반복 설명으로 지지 수를 늘리지 않는다.

공통 입장과 출처별 이유는 별도 필드다. A의 생활비 이유와 B의 자유 이유를 모든 지지자의 이유로 말하지 않는다.
**개인별 필수 이유를 모두 합쳐 공통 입장의 필수 전제로 만들지 않는다.**
공통 명제 자체의 필수 사실과 노출할 출처별 논거의 사실 의존성을 따로 추적한다.
미해결 전제에 의존하는 명제/논거는 노출할 수 없다. 공통 명제 필수 조건·사실 또는 핵심 논거 완전성 불확실은 후보 보류다.
필수 사실 삭제·가치 재분류로 승격하지 않는다. 선언한 주요 사실 근거가 전부 탈락한 후보도 입장만 남겨 구제하지 않는다.
처음부터 가치·규범·예측인 관점은 그렇게 표시하되 사실 확인 완료로 표현하지 않는다.

사실 검사는 **기존 로컬 Kela 증거 자료 묶음**과 DeBERTa NLI를 사용한다.
기준 자료는 `runs/fact-evidence-development-20261013/plan.json`의 document/selections다.
구현 시작 시 문서 원본·선택 범위·만료·hash와 기존 NLI 임계값을 새 plan에 동결한다. 고정40건 정답은 runtime에 전달하지 않는다.
기존 selections는 문서의 세 구간이다. 자료만 재사용하고 과거 rows/agents의 주장별 정답·평가 연결은 가져오지 않는다.
필요 사실을 자료 내에서 검색·대조하되 자료가 없거나 범위가 다르면 보류한다.
NLI는 **해당 자료가 주장을 뒷받침하는지** 검사하는 부품이지 세계의 모든 사실을 보증하는 도구가 아니다.
기존 영어 NLI로 비영어 사실의 검증 완료를 주장하지 않는다. 지원 언어 밖의 사실은 보류하고, 이번에 번역 검증 파이프라인을 추가하지 않는다.
기본은 고정 로컬 자료다. 실제 evidence gap이 확인되면 §6에 따라 필요한 공개 1차자료를 제한적으로 추가할 수 있다.
새 자료는 별도 버전·재검증이 필요하다. 적절한 자료가 여전히 부족하면 보류하며 완료 기준을 낮추지 않는다.

검사 결과를 `agents/grounded_inputs.py`와 `agents/grounded_runtime.py`에 연결한다.
Agent는 허용 입장/논거/인용 ID와 독립 이력을 갖고 동일8B 서버를 순차 사용한다. 가중치를 Agent마다 복제하지 않는다.
생성 수는 동적이며 모든 적격 후보를 노출한다. 지지 수·이유별 제공자 수·보류 이유를 구분한다.
기존 runtime의 근거 선택·제한된 답변 계약을 사용한다. 자유 생성형 채팅이나 Agent 간 토론을 이번에 추가하지 않는다.

## 3. 모듈 계약과 재사용 경계

| 계약 | 필수 정보 |
| --- | --- |
| Source | canonical_id, original_text, parent_context, segment inventory, source_hash |
| MinimalClaim | id, text, source_id, evidence_segment_ids, essential_condition_segment_ids, authorship, extraction_status |
| Candidate | id, canonical_claim_id/text, aliases, nominee_ids, equivalence_refs |
| Membership | source_id, candidate_id, relation, authorship, scope, evidence_segment_ids, request_hash |
| SourceArgument | source_id, claim/candidate links, text/type, essentiality, dependencies, evidence_segment_ids, completeness, audit |
| FactCheck | claim_hash, evidence IDs/hash/scope, verdict, model/config version, expiry |
| AgentSpec | perspective_id, stance, support_ids, source_arguments, allowed_claim_ids, fact_checks, hold_reasons |
| RunManifest | input/code/model/schema/prompt hashes, policy/design versions, stage status, calls/tokens/time/resources |

MinimalClaim authorship는 asserted/explicitly_endorsed/reported/uncertain이며 앞의 두 상태만 작성자 입장 후보가 된다.
‘다른 사람들이 X라고 말한다’는 메타 주장 자체를 작성자가 주장할 수 있으나 X의 지지자로 바꾸면 안 된다.
필드 존재나 segment 연결만으로 의미 보존을 통과시키지 않는다.

새 계약은 버전 있는 별도 모듈/adapter로 구현한다. 기존5필드 frame을 가짜 값으로 채워 통과시키지 않는다.
이 문서의 `factory/`, `agents/` 모듈 경로는 `src/commentscope/` 기준이다.

## 7. 성능 기록과 다음 세션

기본 주장 추출은 `ceil(N/8)`호출이며 용량 분할·추가 추출은 별도다.

전수 원문×후보 비교는 하지 않는다. 호출/토큰·로딩/추론/평가 시간·최소 메모리·실패/partial·유효 관계 수를 함께 보고한다.

checkpoint035/034와 평가기 r5 버전 분리·변경 영향 G0 검증은 r5 최초 구현의 기준점이다. 현재 재개 위치는 `NEXT_SESSION.md`와 거기에 지정된 최신 checkpoint로 확인하며 이미 완료한 최초 작업부터 반복하지 않는다. 압축 후에는 현재 작업의 plan/result 및 필요한 명세 절만 대조한다.
파일별 책임을 짧게 기록한 뒤 G1→G2→G3→G4로 진행한다. 모델 선택 비교를 다시 시작하지 않는다.
인계 산출물은 클러스터·원문 연결·지지 분포·Agent 프로필·실행 결과·검토표·보류·재현 명령이다.
없는 runner 명령을 이미 실행 가능한 명령처럼 README에 쓰지 않는다.

설계 확정은 구현 완료나 의미 품질 통과의 증거가 아니다.


## 8. 구현 방향 보완 — 결정적 원문 구조 (2026-10-16)

진행 중 사용자는 한 영상에 맞춘 프롬프트 수정에 의존하지 말고 여러 영상에 재사용할 수 있는
결정적 처리 구조를 강화하도록 지시했다. §6의 구조 수정 권한 안에서 다음 방향을 적용한다.
완료 조건, 평가 분모, 사실 정책, 모델/자원 선택, G0→G4 순서는 변경하지 않는다.

- 원문 문장·인용·명시적 연결 표현의 범위와 출처 소유 관계를 후보 생성 전에 코드로 고정한다.
- 지원하는 명시 구문에서 이유·양보·필수 조건은 해당 원문의 부모 구절에만 연결한다.
  다른 구절/작성자로 근거를 옮기거나 없는 이유를 생성할 수 없다.
- 규칙은 영상 ID, 주제 단어, 평가 정답을 받지 않는다. 동일 입력/버전은 동일 구조를 반환한다.
  주제 치환, 공백 변형, 인용, 부정된 연결 표현, 중첩 조건을 포함한 별도 대조로 검사한다.
- 다중/부정/지원 밖 연결 구문, 인용의 작성자 귀속 등 애매함은 원문과 함께 보류한다.
  구문 파싱은 의미 해석·사실 확인·작성자 승인·지지 집계의 자동 통과가 아니다.
- 모델은 고정된 구절의 의미·타입·후보 대응을 제한된 계약으로 제안한다. 원문 주소와
  논거의 부모, 필수 조건 보존 규칙, 집계/상태 전이는 코드가 강제한다.
- 자유로운 원문 논거 생성/역할 지정 경로는 이 소유 관계를 검사하는 adapter로 교체한다.
  adapter가 연결되기 전에는 구조 artifact만으로 완료나 G1 통과를 주장하지 않는다.

첫 구현은 `factory/explicit_discourse.py`와 `experiments/explicit_discourse_probe.py`다.
초기 문법은 영어 postfix because/although/even though/only if/only when, 한국어 때만과
명시적 인접 이유 문장의 제한된 범위다. 보편적인 문법/의미 정확도를 보장한다고 주장하지 않는다.
`minimal_pipeline` v7은 이 구조를 실제 source argument adapter와 지지 집계 guard에 연결했다.
`argument_ownership_enforced=true`는 연결 적용을 나타내며 의미 품질 통과가 아니다.
고정 노드 타입/작성자·부모 대응은 모델 해석을 별도로 검증하며, 인용·암시적/복합 구문 등
현재 문법 밖 범위는 원문과 함께 보류한다. 다음은 부품 전수 검토와 새 전체 G1 실행이다.

조건절의 전건은 “조건이 실제 충족됐다”는 독립 사실과 구별한다. 전건은 원문 범위 및
완전한 부모/후보의 조건으로 보존하며, 만족 사실로 승격하지 않는다. 명시적 단순 가능성
표현과 직접 발화의 제한된 문법은 코드로 보존하되 문법 밖 타입/귀속/대응은 여전히 별도
검증 대상이다. 실제로 주장된 사실 근거의 외부 검증과 보류 정책은 그대로다.


G2 실패 후 pipeline v8은 원문 하나를 추출의 독립 처리 단위로 삼는다. 다른 원문의 오류가
정상 원문 기록을 버리지 못하며 partial일 때만 기존 정책의 추가1회를 허용한다.
상태별 JSON 스키마는 non_substantive/unresolved의 새 주장0개와 최초 covered의 주장1개 이상을
강제한다. 문맥이 어려운 원문을 자동 제외하거나 과거 평가 정답을 넣는 경로는 없다.
영상 제목/언어/ID는 버전 있는 선택 문맥으로 snapshot과 정확히 결합한다. 지시어 해석에만
사용하고 댓글 원문 인용/지지/외부 사실 근거로 승격하지 않는다. 문맥 변경은 요청/출처 해시를
바꾸므로 기존 평가 응답을 재사용할 수 없다. 원문별 추출과 문맥 전달은 의미 정확도 보증이
아니며, 같은 개발24개의 부품 대조와 새 전체 G1→G2 검증을 통과해야 채택 증거가 된다.

## 9. r5 선별 분석과 자율 개선 — 2026-10-17

사용자가60% 첫 MVP를 승인했다. 전체 원문은 보존하되 명확하고 검증 가능한 원문부터 후보를 만들고
나머지는 원문+부모+후보의 관계로 연결하거나 보류한다. 선별/상세 분석 비율을 고정60%로 강제하지 않는다.
