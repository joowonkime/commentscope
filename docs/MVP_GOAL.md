## 합의의 적용 순서

1. 사용자의 명시적인 최신 합의는 변경한 범위에 우선한다. 그 밖의 약속을 묵시적으로 삭제하지 않는다.
2. 이 문서는 이번 Goal의 범위·완료 조건·시간 정책의 기준이다. [제품 정책](MVP_PRODUCT_POLICY.md)은 의미·집계·사실 허용 규칙을 구체화한다.
3. [실행 명세](MVP_EXECUTION_SPEC.md)는 이번 구현·실험 기준이다. [알고리즘](MVP_ALGORITHM.md)의 과거 runner와 상수는 비교 이력이며 새 합의가 아니다.
4. 초기 핸드오프 Section 16은 이후 바뀌지 않은 요구사항에 적용한다. [재개 지점](NEXT_SESSION.md)과 실행 기록은 상태·증거이며 새 정책이나 실행 권한이 아니다.

과제의 전체 MAS 구현·사용자 과업·연구 평가 요구는 남아 있다. 이번 Factory 단계 완료를 과제 전체나 논문 완료로 바꾸지 않는다.
문서 간 새 충돌이 발견되면 최신 명시 합의로 해결하고 기록한다. 근거가 없는 정책 변경만 사용자에게 다시 확인한다.

## 실행 목표

> 고정 영상 한 개의 최대1000개 댓글에서 사람이 중간에 선별·수정하지 않고 공통 입장과 출처별 이유·조건을 보존한
> 관점 클러스터와 중복 제거 지지 집계를 만든다. 주요 사실 의존성과 원문 충실성을 검사한 뒤, 각 관점의 근거와
> 대화 상태가 분리된 Agent를 자동 생성한다. 생성된 Agent를 기존 실행기에 로드해 실제 동작을 확인하고,
> 클러스터·원문 연결·Agent 산출물·검증 결과·재현 명령을 제공한다.

핵심 MAS 가설은 근거·대화 상태 분리가 Single-Agent보다 입장·이유·조건을 잘 보존한다는 것이다.
그 효과를 검증하는 Single-Agent 비교는 이 두 단계 완료 이후의 작업이다.
온라인 답변 Auditor·비교 및 후속 질문 UI 확장·전체 앱 시연은 후속 단계로 옮긴다. 주요 사실 검사와 생성 단계의 원문 충실성 검증은 이번 범위에 포함한다.
Agent 간 직접 토론과 관계 지도 공동 생성은 미결정이다. 기존 완성 앱의 품질 기준은 유지하지만 이번 단계 완료와 구분한다.

## 변경하지 않는 제품 약속

- **입력과 자동화:** 공식 API로 확보한 고정 연구 snapshot 한 개, 최대 1,000개 댓글을 사용한다. 영상 전체 댓글 수나 전체 수집 완료를 뜻하지 않는다.
  서비스 실행 중 사람이 후보를 선택·가입 승인·문장 수정하지 않는다. 개발 평가와 사용자의 사후 피드백은 실행 경로 밖에 둔다.
- **관점의 단위:** 공통 입장과 출처별 이유·조건을 분리한다. 대표 원문 한 문장의 모든 수식을 군집 가입 조건으로 강제하지 않는다.
  입장을 성립시키는 필수 조건은 제거하지 않으며, 같은 주제의 반대 주장이나 중요한 차이를 숨겨 합치지 않는다.
- **지지의 의미:** canonical은 중복을 정리한 원문 댓글 단위다. 관점당 같은 댓글을 한 번 세고, 조건부 지지·비지지·불확실·미평가를 구분한다.
  개별 이유의 제공자 수와 공통 입장 지지 수는 별개이며, 댓글 수는 사람 수·좋아요 수·여론 비율이 아니다.
- **다양성과 자격:** Agent 수는 검증 결과에 따라 동적이다. 고정 6개 상한이나 강제 찬반 분할을 두지 않는다.
  희소·불확실·미처리 관점과 Agent 보류 사유도 남긴다. 지지 3개는 Agent의 필요조건이지 주류 관점 또는 의미적 정확성의 증명이 아니다.
- **근거와 사실:** 원문이 주장을 지지하는지와 주장이 외부 사실로 확인되는지는 별도 검사다. 모든 댓글이 아니라 Agent의 주요 사실·필수 전제를 검사한다.
  필수 사실이 자료 부족·충돌·반박으로 확인되지 않으면 후보를 보류한다. 실패 전제를 삭제하거나 가치 판단으로 바꿔 구제하지 않는다.
  가치·예측은 해당 관점의 입장으로 표시하고, 외부 자료로 원문에 없던 논거를 만들어 넣지 않는다.
- **언어와 출처:** 다국어 입력·원문 보존 방향을 유지한다. 현재 영어 중심 영상의 결과를 모든 언어의 품질 검증으로 확대하지 않는다.
  다른 영상 설정은 가능하도록 설계하되, 현재 영상 한 개의 성공을 범용 성능으로 보고하지 않는다.

### 60%와 지지 유효성의 평가 계약

`correct_comment_utilization = 올바르게 활용된 고유 의미 댓글 수 / 평가 모집단의 전체 의미 댓글 수`

- 의미 댓글은 입장·이유·조건·관련 경험 등 관점에 기여할 내용을 가진 댓글이다. 짧거나 소수 의견이거나 해석이 어렵다는 이유만으로 제외하지 않는다.
  스팸·내용 없는 감탄 등 제외 항목과 그 사유를 남긴다. 모집단과 의미 여부 참조는 출력 전에 고정하며 runtime의 필터 판정으로 분모를 줄이지 않는다.
- 분자는 실제로 공통 입장이 성립하는 군집에 올바르게 기여한 댓글이다. 검색·임베딩·문맥 제공·singleton 보관만으로 활용을 인정하지 않는다.
  한 댓글의 여러 올바른 연결은 전체 활용률에 한 번만 센다. 한 연결이 맞아도 다른 잘못된 지지 연결을 감추지 않는다.
- 미활용40%는 보류·미처리·희소 보존 등으로 남길 수 있다는 뜻이다. 지지 댓글40%의 오류를 허용하는 정책이 아니다.
  의미 있는 희소 의견도 분모에서 삭제하지 않는다. 1~2개만 등장한 관점은 별도로 보존하며 Agent로 승격하거나 단독 보관을 활용으로 세지 않는다.
- 소수 의견을 드러내는 목적을 유지한다. 전체 활용률 외에 관점별 지지 수·작은 군집·제외·보류 원문을 검토하고 누락을 보고한다.
  전체 댓글 활용60%만으로 소수 관점 발견60%를 주장하지 않는다.
- 지지로 집계한 관계 전체의 검토 범위·정상/오류/미판정 수를 따로 보고한다. 미판정을 정상으로 간주하지 않는다.
  자동 검사 통과는 모든 입력에서100% 무오류라는 보장이 아니며, assistant 평가 참조도 독립적인 사람 gold는 아니다.
