# CommentScope MVP 완주 지도와 선택 인계

2026-11-20 · TASK-039 · REQ-009~012. 확인 기준은 main `0bf22f7`이다.
사용자 경험은 DEC-030에 확정되어 있다. 이를 구현할 합의 방식, 새 API와 저장 구조는 DEC-029의 제안이다.
이 문서는 구현 차이와 담당 범위를 안내한다. 상세 계약은 각 작업에서 연결한 문서를 따른다.

## 1. 우리가 정한 흐름

| 단계 | 사용자가 할 일과 얻을 것 |
| --- | --- |
| 시작 | 지원 영상의 댓글 분석을 연다. M4에서는 사전 분석된 선정 영상으로 시작할 수 있다. |
| Explore | 근거 제약을 통과한 초기 Agent 전부에서 관점·근거·조건을 살펴보고 토론 참가자를 직접 고른다. 화면의 토론 정원과 전체 Agent 수는 별개다. |
| Converse | 쟁점이나 질문을 정해 한 번 시작한다. 선택한 Agent들의 발언과 상대 주장에 대한 응답이 턴 순서로 나타난다. 진행 중과 종료 후에 기록을 읽고 원문으로 이동할 수 있다. |
| 최종 결과 | 같은 실행이 자동으로 결론까지 이어진다. 공동 주장·합의 조건·남은 이견과 근거를 보여 준다. 유효한 합의가 있으면 별도 합의 Agent를 제공한다. 합의가 없거나 검증이 보류된 경우에도 결론과 기록을 읽을 수 있다. |
| Reflect | 합의 Agent가 있으면 후속 질문으로 범위와 근거를 확인한다. 사용자는 원래 관점과 결과를 바탕으로 자기 판단을 정리하고 저장·재열람한다. |

세 사용자 과업은 **관점과 근거 탐색 → 토론과 결론 확인 → 자신의 판단 정리**다.
합의 정리와 Agent 생성은 서버가 진행한다. 사용자는 어떤 조건에 합의했고 어떤 주장이 남았는지 확인할 수 있어야 한다.

## 2. 구현과 완주를 막는 지점

| 구간 | 현재 확인된 동작 | 부족한 기능과 완료 확인 |
| --- | --- | --- |
| 선정 영상 준비 | `tools/prepared_video_trial.py`에서 snapshot을 분석하고 제품에 등록할 수 있다. 기존 웹은 첫 가용 분석을 연다. | 제출에 사용할 지원 영상과 분석본을 지정한다. 실제 원문과 서로 구별되는 관점이 있어야 하며, 새 접속에서 바로 고를 수 있는지 확인한다. 임의 URL 분석·별도 홈·장기 기록은 추가 범위다. |
| Agent 생성과 목록 | Factory와 Compiler가 있고, 제품은 현재 compiled profile을 전부 순회한다. 합성 12개 전부 반환과 마지막 2개 선택 유지를 확인했다. | 새로 전체 목록 API를 만드는 작업보다 실제 입력에서 출처가 맞고 구별되는 관점을 얻는 일이 남았다. 실제 180댓글 실행은 각 출처 1개인 두 관점에 그쳤고, 승인된 원댓글 이유는 0개였다. 적격 0·1개와 겹치는 관점을 다루는 화면도 확인한다. |
| 토론 시작과 상대 응답 | 기존 그룹은 선택한 참가자의 opening/reply를 게시한다. 2명은 4턴 뒤 `awaiting_user`다. 마지막 타 Agent 발언을 reply 문맥으로 쓰며 원질문은 일반 reply 지시로 바뀐다. | 원질문과 답할 상대 주장을 함께 전달한다. 필터링 후 실제 응답이 남았는지 보고, 한 번 시작한 실행이 결론까지 이어져야 한다. 새 토론 API는 확인 시 404였다. |
| 합의 평가 | 제품에서 합의 후보 작성, 개별 수락 확인, 근거가 충족된 공통 주장 집계가 없다. | 각 관점의 입장·조건·근거와 구체적인 수락 여부를 보존한다. 합의 없음, 검증 보류, 응답 미충족, 실행 실패를 각각 구별한다. |
| 최종 결론과 합의 Agent | 기존 방 응답에는 최종 결론과 파생 Agent 참조가 없다. | 메시지 끝에 결론과 이견을 표시하고, 유효 합의에 한해 별도 Agent를 저장한다. 새로고침에서 같은 결과로 돌아오고 중복 클릭으로 새 비용이나 Agent가 생기지 않아야 한다. |
| 후속 질문과 성찰 | 기존 Agent 1:1, 원문 조회, Reflect 편집·저장·복원이 작동한다. | 합의 Agent에 질문하고 원 출처와 부모 관점으로 돌아가는 연결이 없다. 대화와 결론의 근거를 찾아 사용자 성찰에 참조할 수 있게 한다. |
| 답변 품질과 속도 | 실제 8개 1:1 질문과 그룹 4턴을 실행했다. 새 이유 1/2, 연구 설명 0/2였고 그룹의 구체적 상호 대응이 약했다. 그룹 4턴은 약 42초였다. | 여러 질문과 참가자 조합에서 남은 답변의 충실도·유용성을 본다. 첫 발언과 최종 결론까지 걸린 시간, 실패·보류·실청구를 함께 기록한다. 자동 합의 전체 시간은 실측할 항목이다. |
| 채점 환경 | 로컬 개발 화면과 합성 재현이 있다. 실제 시험의 생성 기한은 종료됐고 지난 감사에서 기존 로컬 주소는 연결되지 않았다. | 최종 빌드·등록 분석·브라우저 접근 URL·유효한 실행 기한·공유 비용 설정을 맞춘다. 다른 환경에서 처음 열어 새 질문을 하는 경로까지 시험한다. |

관점 수와 자동 토론의 연결은 별개의 실패 지점이다. 실제 자료에서 쓸 만한 관점이 적으면 연결을 완성해도 선택 가치가 낮다. 반대로 목록에 충분한 관점이 있어도 결론과 후속 질문에 도달하지 못하면 선언한 흐름을 완주할 수 없다.

근거와 재현 방법은 [현재 구조](design/IMPLEMENTED_STRUCTURE.md), [실제 영상 실행](design/PREPARED_VIDEO_WEB_RESULT.md), [M4 준비도 감사](M4_PROTOTYPE_REVIEW.md)에 있다.

## 5. 팀에 일부만 넘길 때

**추천은 프론트와 QA 두 묶음이다.** 중앙 통합 담당은 032~035의 공통 계약과 027의 실제 품질 진단을 연결한다. 아래에서 필요한 묶음의 링크만 보내도 된다. 역할과 인원은 팀에서 정한다.

### A. 화면과 프론트

- **Issue 제목** — 관점 선택에서 토론 기록·최종 결과까지 화면 연결.
- **시작 자료** — 현재 `/mvp`와 기존 Compare·Converse·Reflect 흐름. 새 화면은 전체 목록, 참여자 선택, 진행 중, 정상 합의, 합의 없음, 보류/실패의 합성 상태를 사용한다.
- **담당 파일** — `src/commentscope/product/mvp.html`, `mvp.css`, `mvp.js`와 담당 화면 모듈. 새 API의 경로와 상태 이름은 통합 담당이 공유한 계약을 따른다.
- **완료 조건** — 0·1·여러 관점, 다른 참가자 조합, 진행/결론/재열람, 근거 출처 표시와 후속 질문 진입을 확인한다. 합성 UI 확인과 실제 연동 상태를 PR에 적는다. 최종 Figma 편집이나 새 API 구현은 각 담당 범위에서 따로 다룬다.
- [화면과 API 대응](design/DEBATE_SYNTHESIS_API.md#a-05-figma와-프론트-연결) · [무료 화면 실행](TEAM_START.md)

### B. 초행 사용과 기능 QA

- **Issue 제목** — M4 세 과업의 시연 밖 기능 점검.
- **시작 자료** — 기존 합성 `/mvp`에서 관점 선택·비교·1:1·그룹·근거·Reflect를 재현한다. 새 기능은 구현 후 확인할 기대 동작으로 기록한다.
- **산출물** — 테스트 표에 시작 상태, 행동, 기대 및 관측 결과, 재현 순서, 막힌 사용자 과업을 적는다. 다른 참가자, 빈 의견, 대본 밖 질문, pause/close, 중복, reload/뒤로가기, 0/1개, 합의 없음, 만료를 포함한다.
- **완료 조건** — 기존 제품에서 지금 확인할 수 있는 사례와 새 기능이 있어야 확인할 사례에 각각 증거가 있다. 최종 통합 후에는 외부 환경에서 실제 질문·결론·저장까지 같은 표로 재검증한다.

## 6. M4에서 완료라고 말할 조건

1. 새 세션에서 선정 영상을 열고, 전체 적격 Agent 중 원하는 참가자를 고른다.
2. 한 번 시작해 발언과 근거를 읽다가 최종 결론·조건·이견에 도달한다. 합의가 유효하면 Agent에게 질문하고, 합의가 없으면 그 이유와 기록을 확인한다.
3. 성찰을 저장하고 새로고침 후 같은 대화·판단으로 돌아온다.
4. 서로 다른 실제 질문/선택에서도 반복 확인하고, 새 사용자가 채점 환경의 URL에서 별도 도움 없이 핵심 과업을 수행한다. 대표 화면·사용 안내는 그 빌드에서 캡처한다.

11월 19일 감사에서는 기존 Chromium 합성 25개·제품 회귀 28개가 통과했다. 이번 제품 소스 대조와 무료 재검사에서도 논점은 같다. 기존 그룹은 열리고 저장되지만 자동 최종 결과와 파생 Agent로 이어지는 구현, 그 경로의 실제 응답·사용성 검증이 남아 있다.
