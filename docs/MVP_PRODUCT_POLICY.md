# 시연 MVP의 제품 정책과 평가 구조

2026-10-13 후속 합의는 **MVP 중심 평가를 사용하고 관계 정밀도·지지 보존율은 유지하되, 그 두 수치만으로 전체를 판단하지 않는다**는 것이다.
95%·80%를 더 낮은 숫자로 대체한 합의가 아니다. 기존 목표를 계속 측정·보고하면서 실제 산출물의 대표성, 왜곡, 답변, 출처와 비용을 함께 평가한다.
이 문서의 변경 범위에서는 과거의 관계 지표 단독 전체 차단 정책보다 이 합의가 우선한다. 이전 실험의 실패·미실행 기록은 바꾸지 않는다.

정책과 별도로 [알고리즘·모듈 책임·Goal 작업 순서](MVP_ALGORITHM.md)를 관리한다. 의미 모델의 판단과 코드가 보장하는 계약을 구분한다.

## 다양한 관점의 발견과 지지 분포가 우선인 Goal

2026-10-14 사용자는 초기 의도를 **유의미한 관점의 약80%를 발견하고, 각 관점이 얼마나 지지받는지 집계한 뒤
다양한 의견의 Agent를 생성하는 것**으로 명확히 했다. 성공 단위를 ‘안전한 Agent2개’로 축소하지 않는다.
Agent2개는 시연의 최소조건이며 관점 포괄성의 증명이 아니다. Agent 수는 발견·검증 결과에 따라 동적이고 찬반이나 개수를 강제로 맞추지 않는다.
관점은 단순한 찬성/반대 두 분류가 아니다. 같은 정책을 지지하더라도 노동 선택이나 경제 효과에 관한 서로 다른 실질 명제를
독립적으로 주장한다면 별도 관점 후보가 될 수 있다. 다만 개별 이유를 구별했다는 것만으로 지지3개나 Agent 적격성을 얻지는 않는다.
앞선 대화의 상세 분석 표본 한도, Agent6개 상한, 단계별 시간 배분안은 확정된 신규 기준이 아니다.

관점 발견→전체 댓글 연결·지지 집계→주요 사실·Agent 적격성→질문·비교·출처 흐름을 분리한다.
Agent로 승격되지 않은 관점도 발견·집계 기록에는 남긴다. 이것은 미검증 사실을 Agent가 사용하도록 허용한다는 뜻이 아니다.
전체 댓글을 연결 대상으로 두되 모든 댓글×관점 쌍에 LLM을 호출하라는 요구는 아니다. 검색에서 제외되거나 아직 판정하지 않은 관계는
미평가이며 비지지로 취급하지 않는다. 일부 검색 후보의 지지 수를 전체 corpus의 확정된 지지 규모로 표시하지 않는다.

| 지표 | 분모와 해석 |
|---|---|
| 관점 발견율 | 사전에 고정한 기준 관점 중 충실하게 대응되는 서로 다른 발견 관점의 비율. 목표는 약80% |
| 댓글 연결률 | canonical 비어 있지 않은 전체 댓글 중 하나 이상의 관점에 지지로 연결된 고유 댓글 비율. 관점 발견율과 별개 |
| 관계 평가 범위 | 관점별 전체 canonical 댓글 중 실제 판정한 수와 미평가 수. 불확실 판정도 별도 표시 |
| 관점별 지지 | 해당 공통 명제를 지지한다고 판정한 고유 댓글 수. 조건부 관계·불확실·미평가는 확정 지지와 분리 |
| Agent 전환 | 발견 관점 중 주요 사실과 원문 충실성 등 기존 적격성을 충족해 Agent로 연결된 수와 보류 사유 |

기준 관점 목록이 없으면 관점 발견율은 **미측정**이다. 80%의 정확한 통과 규칙, 관점 구분 단위, 평가 범위와 대응 판정은
새 실험 전에 고정해야 한다. 일부 표본에서 만든 기준으로 평가했다면 그 표본의 발견율이지 전체 영상의80%라는 증거가 아니다.
하나의 모호한 관점을 여러 기준 관점에 중복 대응시켜 발견율을 부풀리지 않는다. 빈도가 높은 관점만 발견해 댓글 연결률이 높아도
다양한 관점을 발견했다는 증거는 아니다. assistant가 만드는 평가 초안은 독립 gold가 아니며 runtime 입력으로 사용하지 않는다.

기존 관계100건의 보존율80%와 이번 **관점 발견율 약80%는 분모가 다른 목표**다. 기존 관계·사실·응답·시간 기준과 실패 기록,
추론8시간 한도, 무인 실행·비공개 자료·외부 서비스 권한 제한은 유지한다. 플랫폼 Goal 문자열은 아직 변경하지 않았고,
최신 제품 목표와 그 해석은 이 절과 아래 군집 정의에 기록한다.

## 공통 입장과 출처별 차이를 보존하는 군집 정의

2026-10-14 사용자는 **문장 전체의 일치가 아니라 실제로 공유하는 입장으로 묶고, 조건과 이유는 출처별로 보존하는 방식**에 동의했다.
군집은 같은 대표 문장에 동의하는 댓글 집합이 아니라, 동일한 대상에 대한 공통 입장과 중요한 차이를 추적할 수 있는 주장 집합이다.
대표 원문 하나의 모든 수식과 이유를 구성원 전체의 가입 조건으로 삼는 설계는 이 정의를 구현하는 기본 방식으로 사용하지 않는다.
이것은 새 설계 원칙의 합의이며 기존 결과의 재승인이나 새 알고리즘의 구현·성능 검증 완료가 아니다.

- 공통 입장에 대한 지지와 즉시성·금액·개인 경험·개별 이유에 대한 지지를 구분한다. 주변 표현과 필수 조건의 구별도 의미 검증 대상이다.
- 조건부 찬성은 무조건 찬성의 확정 지지 수에 넣지 않는다. 조건부 관계 또는 별도 하위 관점으로 보존한다.
  여러 댓글이 동일한 조건부 명제를 실제로 공유하면 그 명제를 가진 별도 후보가 될 수 있지만 최소 지지 기준은 그대로 적용한다.
- 원문에 명시된 도입 요구의 시점은 출처별로 남길 수 있으나, 시점이 찬성의 전제라면 이를 제거해 공통성을 만들지 않는다.
- 이유는 제시한 작성자에게만 귀속한다. 공통 입장 지지 수와 이유별 제공자 수를 합산하거나 서로 대체하지 않는다.
- 원문 인용은 그대로 보존하고, 의미를 바꾸지 않는 공통 입장 설명은 인용과 구분한다. 설명의 대상·태도·조건을 원문에 대조한다.

합성 예로 A가 ‘정책 P를 즉시 도입해야 한다, 이유는 생활비’, B가 ‘P 도입에 찬성한다, 이유는 선택의 자유’,
C가 ‘재원이 확보된다면 P 도입에 찬성한다’고 말한다면 A·B는 도입 찬성을 공유한다. 즉시성은 A의 요구이고 이유는 각 출처의 것이다.
C는 무조건 찬성의 지지 수에 합산하지 않는다. 이 예의 무조건 지지는2개이므로 Agent 최소 지지3개를 충족하지 않는다.

Goal의 관점 형성은 이 정의를 따른다. 기존 수치·예산·주요 사실 제한·무인 실행·비공개 자료 원칙은 변경하지 않는다.
잘못된 포함과 과도한 제외를 구분해 평가하되, 새 표본 구성·허용 오류 수·합격 기준 변경까지 승인된 것으로 해석하지 않는다.

## 현재 Goal과 적용 우선순위

2026-10-13 사용자가 대화 압축 뒤 목표·정책을 먼저 재확인하도록 요청했다. 이번 재정리는 새로운 기준 완화나 실험 승인이 아니다.
현재 작업 목표는 **한 영상의 고정 댓글 snapshot에서, 서비스 중 사람의 선택·수정 없이 다양한 유의미한 관점의 약80% 발견을 목표로
전체 댓글에 대한 관점별 지지 분포를 만들고, 주요 사실 근거를 검사한 뒤 각 관점을 대변하는 Agent와 비교·후속 질문·출처 확인까지
실제로 작동하는 로컬 시연 MVP**다. 관점 발견율의 기준 목록과 평가 범위는 위 절대로 별도로 고정해야 한다.
클러스터링 점수만 올리는 연구, 토론하기 좋은 찬반을 억지로 만드는 일, 합성 Agent만으로 화면을 완성하는 일은 이 목표의 대체물이 아니다.

프로젝트 요구사항의 적용 순서는 다음과 같다. 이것은 시스템·안전 지시의 우선순위를 바꾸는 규칙이 아니다.

1. 사용자의 명시적인 최신 합의. 변경한 범위에만 적용하며 다른 조건을 자동으로 삭제하지 않는다.
2. 이 제품 정책의 현행 기준과 [알고리즘 문서](MVP_ALGORITHM.md)의 실행 책임.
3. 초기 핸드오프 Section 16의 미변경 요구사항. 이후 합의로 바뀐 수동 fallback·평가·시연 범위는 최신 합의를 따른다.
4. [재개 지점](NEXT_SESSION.md)과 실험 기록은 상태·증거다. 과거의 “다음 작업” 문구는 현재 정책이나 새 실행 권한이 아니다.

플랫폼 Goal은 예산 승인 대기로 blocked이며 objective 문자열에는 초기 수치 기준이 남아 있다. 문자열 자체를 수정했다고 보고하지 않는다.
관계95%·80%는 계속 측정·보고하되, 미달만으로 통합 실행과 제품 평가 전체를 금지하지 않는 후속 합의를 함께 적용한다.
MVP 통과와 모든 수치 목표 달성을 구분한다. 관계 목표가 미달이면 그 사실을 남기고 모든 Goal 조건 충족·논문 검증 완료로 표시하지 않는다.

### 유지하는 범위와 실행 권한

- 고정 영상1개·최대1000댓글을 우선 시연한다. 나중에 다른 영상을 설정할 수 있어야 하지만 임의 URL을 받는 공개 서비스는 범위 밖이다.
- 전체 cluster가 아니라 충분한 원문 지지와 근거 제한을 만족한 관점만 Agent가 된다. 수는 동적이며 서로 다른 Agent2개 이상이 시연 필요조건이다.
- 다국어 입력과 원문 보존이라는 설계 방향을 없애지 않는다. 현재 영어 중심 표본의 결과를 다국어 품질 검증으로 확대 해석하지 않는다.
- 희소·불확실·미처리 관점을 다수 의견으로 승격하지 않는다. 원문·처리 상태·누락량을 보존하며, 지지 댓글 수는 사람 수나 여론 비율이 아니다.
- Reflection과 자유로운 Agent 간 토론, 여러 영상의 연구 평가는 후속 제품·연구 항목으로 남긴다. 현재 비교·질문·출처 MVP의 완료와 구분한다.
- 로컬 실행과 기존 모델을 우선한다. 공개 저장소에는 코드·사용법·합성 예시를 올릴 수 있지만 실제 댓글·모델 출력·비밀키는 올리지 않는다.
- 유료 API, 새 대용량 모델 다운로드, 외부 모델에 댓글 전송, 공개 배포, main 병합은 별도 승인 없이 하지 않는다.
- 실패·중단 추론을 포함한 기존8시간 ledger를 유지한다. 대화 압축·세션 재개·정책 재정리는 예산이나 실패 이력을 초기화하지 않는다.

### 혼동하면 안 되는 상태

코드 테스트 통과, 모델상 지지3개 이상 후보, 사실 제한을 통과한 Agent 입력, 실제 내용 검토 통과, 전체 시연 MVP 통과,
논문용 독립 검증은 서로 다른 상태다. 앞 단계의 성공을 뒤 단계의 완료로 바꾸지 않는다.
개발 중 assistant가 결과를 검사하는 것은 허용하지만 평가 라벨·수정 문장·선별 결과를 서비스 runtime에 넣지 않는다.
실제 제품 평가에는 자동 노출되는 모든 Agent를 포함한다.

## 목표 중심 변경 원칙

2026-10-14 최신 사용자 지시에 따라 개별 오류를 위한 자잘한 수정의 반복보다 **다양한 관점의 발견·지지 집계·무인 Agent 시연 완성**에
기여하는 병목 제거를 우선한다. 성공의 단위는 prompt나 테스트 하나가 아니라 원문에서 질문·출처 UI까지의 전체 경로다.

각 변경은 구현 전에 해결하려는 제품 병목, 바꿀 모듈, 유지할 계약, 검증 분모와 추론 예산, 채택·기각 조건을 명시한다.
판정 문구·임계값·처리 순서·참조 정답을 결과에 맞춰 동시에 바꾸지 않는다. 실행 중 발견한 사례는 다음 판단의 증거로
보존하며 현재 실행을 고쳐 합격시키지 않는다. 재현 가능한 실행 오류 수정과 의미 품질의 구조 변경도 구분한다.

정책은 원문 왜곡·필수 사실 우회 금지와 불확실성 표시를 정한다. 알고리즘은 후보 형성, 지지 검색, 출처별 이유 연결,
완료 예산을 담당한다. 프롬프트는 고정된 모델 입출력 계약을 표현하며, 사례별 예외 목록을 늘리는 기본 해결책으로 쓰지 않는다.
코드가 보장할 수 있는 ID·작성자·인용·예산 계약과 여전히 실험해야 하는 의미 판단을 별도로 보고한다.

수정 후에는 자동 노출 Agent 수와 전수 내용 검토, 전체 시간, 미처리 범위를 함께 비교한다.
부품 지표만 좋아지고 유효 Agent 수·원문 충실성·실행 시간 중 제품 병목의 개선이 확인되지 않으면 MVP 개선으로 채택하지 않는다.
제한된 cached 진단은 다음 구조를 결정하는
증거일 뿐 fresh1시간 달성 증거가 아니며, 기존 실패와 누적8시간 예산을 초기화하지 않는다.

## 진단 실행과 시연 승인

fresh runner 0.3은 평가용 통합 실행과 시연 승인 상태를 분리한다. `product_diagnostic`은 실패·부분 관측된 관계 측정을
그대로 보존하면서 실행을 허용한다. `qualified_configuration`은 완전한 관계 검사 통과를 계속 요구한다.
두 모드 모두 Agent·MVP·논문 검증을 자동 승인하지 않는다. staged runner의 기존 gate는 아직 그대로이며,
새 source-first 경로의 실제 의미 품질은 미검증이다.

## 무엇을 만드는가

한 영상의 최대1000개 댓글에서 유의미하고 서로 구별되는 관점을 자동으로 찾아, 그 관점의 입장·이유·조건과 출처를 설명하는 Agent를 만든다.
전체 댓글의 완전한 요약, 여론 대표성, 모든 작성자가 동일한 이유를 공유한다는 보장은 하지 않는다.
서비스 중 사람이 후보를 골라 주거나 문장을 고치거나 가입을 승인하는 단계는 넣지 않는다.

공통 입장과 이유별 출처는 분리한다. 같은 주제라는 이유만으로 반대 입장을 묶지 않고, 중요한 조건 차이를 하나의 무조건적 주장으로 지우지 않는다.
공통 입장이 실제로 성립하지 않으면 하위 관점으로 나누거나 보류한다. 관점 수를 맞추기 위한 강제 분할도 하지 않는다.
일부 구성원만 제시한 이유는 그 구성원의 이유로 표시하며 전체 집단의 공통 논거로 바꾸지 않는다.

## 제품 통과 조건과 진단 목표

아래 수치는 기존 합의에서 가져온 개발·시연 기준이다. 보편적인 연구 표준이나 모집단 성능의 통계적 보장은 아니다.

| 평가 층 | 유지할 기준 | 판정에 쓰는 방식 |
|---|---|---|
| 실제 관점 형성 | 서로 다른 Agent≥2, 각각 canonical 지지≥3 | 자동 산출물에서 확인할 MVP 필요조건. 원문 대변·논점 차이도 함께 검사 |
| 원문 관계 | 고정100관계 정밀도 목표≥95%, 정상 지지 보존 목표≥80% | 계속 보고하는 진단 목표. 미달만으로 통합 실행 전체를 차단하지 않으며, 미달 원인과 실제 출력 영향을 함께 공개 |
| 주요 사실 | 고정40건 중 비지원 오승인0, 지원≥8/10 | 사실 판정 부품 기준을 유지. 실제 Agent가 사용하는 주요 사실의 출처·범위도 별도 검사 |
| 실제 Agent 내용 | 핵심·주요 근거 전수검토에서 입장 반전·이유 전이·근거 없는 사실 승격·인용 조작0 | 관측된 중대한 왜곡은 시연 승인 실패. 검사 대상 전체와 오류 수를 보고하며 보편적 무오류를 주장하지 않음 |
| 실제 답변 | 답변 가능·근거 부족 질문의 적절성 각각≥90% | 실제 자동 생성 Agent의 사전 고정 질문으로 측정. 합성 Agent 부품 점수로 대체하지 않음 |
| 사용자 흐름 | 관점 비교·후속 질문·원문 확인 | 실제 자동 산출물로 끝까지 작동해야 함 |
| 시간 | 저장 snapshot에서 첫 준비≤1시간, 준비된2-Agent 비교20회 P95≤60초 | 모델 로딩과 분석을 포함한 실제 측정. cache 재생 시간으로 대체하지 않음 |
| 개발 비용 | 새 사이클 누적 추론≤8시간 | 실패·중단 비용 포함. 새 합의로 예산을 초기화하지 않음 |

정밀도는 승인한 관계를, 보존율은 평가에서 정상 지지로 분류한 관계를 분모로 사용한다. 100건 중 정상19건인 현재 평가에서는
정상16건과 오승인1건이면 정밀도가16/17=94.1%다. 작은 분모의 문턱 효과를 전체 제품의 유용성과 동일시하지 않는다.
반대로 숫자가 높아도 실제 Agent가 입장을 뒤집으면 제품 통과로 처리하지 않는다. 임의의 가중 평균 점수로 중대 오류를 상쇄하지 않는다.

모든 자동 노출 Agent가 제품 검토 대상이다. 사람이 잘 나온2개만 고르거나 나머지를 수동으로 삭제해 합격시키지 않는다.
검토는 개발 결과 평가이지 서비스 실행 중 수동 승인 절차가 아니다. assistant 평가는 독립 gold나 논문용 독립 검증이 아니다.

## 허용하는 요약과 허용하지 않는 왜곡

- 표현 차이, 의미를 바꾸지 않는 압축, 주변 세부사항 누락은 그 자체로 중대한 오류가 아니다.
- 작성자 변경, 찬반 반전, 필수 조건 삭제, 개인 경험의 집단 일반화, 이유·인과의 발명은 의미를 바꾸므로 별도 오류로 기록한다.
- 애매한 경계 관계는 불확실성으로 남긴다. 불확실한 관계를 확정 지지 수에 더하지 않는다.
- 판단에 필요한 문맥이 없는 댓글은 원문을 보존하되, 없는 문맥을 모델 상식으로 보충하지 않는다.

이 분류는 단어 목록으로 판정하는 새 필터를 뜻하지 않는다. 평가자는 원문과 출력에서 실제 의미가 바뀌었는지 확인하고,
오류의 범위와 영향을 기록한다. 모호한 평가 참조를 사후에 고쳐 이전 실행을 합격시키지 않는다.

## 구조와 비용 배분

```text
고정 snapshot과 출처
  → 의미가 가까운 후보 검색
  → 원문별 주장·입장·조건과 불확실성
  → 양립 가능한 관점 묶음
  → 공통 입장 + 이유별 근거 + 조건 차이
  → Agent가 사용할 주요 사실만 검사
  → 허용 입력 조립
  → 비교·후속 질문·원문 UI

별도 개발 평가: 고정 관계100건 + 실제 Agent 내용 + 실제 질문 + 시간·누락량
```

후보 검색은 비교할 대상을 좁히는 역할이며 의미 지지 판정이 아니다. 대표 문장 하나에 모든 댓글을 맞추거나,
전체 댓글의 모든 쌍을 반복 검사하는 구조를 기본값으로 삼지 않는다. 원문별 분석은 재사용 가능한 단계 산출물로 보존한다.
후보의 이름·설명과 실제로 공유되는 주장을 구분하고, 상세 이유와 조건은 각 출처에 연결한다.
기존 수집·임베딩·출처 계약·사실 검사·응답 UI는 재사용하되 이 구조의 의미 품질은 실제 실행으로 다시 확인해야 한다.

고비용 사실 검사는 모든 댓글이 아니라 Agent가 사용하는 주요 사실에 집중한다. 원문에 없는 근거를 외부 자료로 보강하지 않는다.
평가 라벨은 runtime 입력·가입 수정·후보 선택에 전달하지 않는다. 코드로 강제할 수 있는 ID·중복·인용·예산 계약은 계속 강제한다.

지지 수는 canonical 댓글 수이지 사람 수나 여론 비율이 아니다. 공통 입장과 각각의 이유에 대한 수를 따로 표시한다.
전체 수집 수, 분석한 고유 댓글 수, 관점에 연결된 고유 댓글 수, 보류·미처리 수를 구분한다. 여러 이유의 수를 더해 전체 지지 수로 쓰지 않는다.
모델 판정 지지 수를 전수 검증된 지지 수처럼 표시하지 않는다. 평가하지 않은 전체 corpus의 의미 recall은 추정하지 않는다.

## 아직 바꾸지 않은 사실 정책

미검증 사실에 의존하는 관점도 Agent가 소개하도록 허용하는 제안은 아직 승인되지 않았다.
따라서 현재의 사실 입력 제한과 핵심 필수 전제 미검증 시 후보 보류를 유지한다.
가치·예측은 그 관점의 입장으로 표시하고, 실패한 사실 전제를 지워 순수 가치로 바꾸는 우회는 금지한다.
평가 정책 변경을 사실 주장 허용 범위의 변경으로 해석하지 않는다.

## 구현 순서와 상태 보고

1. 정책 버전과 실패 유형을 먼저 고정한다. 관계 목표 충족, 제품 통과, 논문용 검증 여부를 서로 다른 상태로 저장한다.
2. 미달 구성도 제품 평가를 위한 통합 실행은 가능하게 하되, 자동 시연 승인·기존 실패의 합격 전환은 허용하지 않는다.
3. 원문별 주장·조건과 공통 입장·개별 이유의 경계를 실제 Factory 산출물까지 연결한다. 국소 문자열 veto 반복은 재개하지 않는다.
4. 자동 산출물을 고정한 뒤 전체 노출 Agent, 실제 질문, 출처 UI와 시간·누락량을 검사한다. 문제를 사람이 고쳐 만든 결과는 자동 MVP 증거가 아니다.

관계100건이 중간에 끝났다면 부분 관측과 상한만 보고한다. 새 제품 평가 실행에서는 관계 목표의 상한 미달만으로 모든 후속 검사를
조기 종료하지 않는다. 예산·계약 오류·실행 실패의 중단 조건은 유지한다. 새 요청·참조·코드·모델·시간 예산은 실행 전에 동결한다.
제품 기준을 충족하더라도 관계 목표 미달은 남겨 두며, 이를 모든 품질 목표 달성이나 논문 검증 완료로 발표하지 않는다.
