# MVP 사용자 확인 절차 — 준비본

TASK-012, REQ-009/010. 아직 참여자 평가를 실시하지 않았다. CI·개발자 검토·Figma 완성도와
사용자의 이해 향상은 별개다. 정식 품질을 통과한 고정 분석을 사용하며, 개발용 합성 자료를 실제 댓글로 소개하지 않는다.

사용자 확인 전의 자료 선정/개발 QA는 [영상 성격별 후보와 QA 계획](design/VIDEO_SELECTION_QA.md)을 따른다.
실제 댓글 표본을 본 예비 후보이며 Agent 자격·정식 평가 통과를 뜻하지 않는다.

## 초행 기능 QA

프로토타입은 사전 등록한 영상에서 시작한다. 실제 댓글과 자동 생성 관점이 있는
[CNBC 주 4일제 분석](MVP_REAL_VIDEO_VALIDATION.md)으로 아래 과업을 시작한다.
테스터에게는 시작 URL과 과업만 주고, 도움 없이 도달한 단계와 막힌 화면을 기록한다.

| 과업 | 기대 동작 |
| --- | --- |
| 영상의 여러 관점을 찾아보기 | 영상과 초기 의견 화면을 연다. 의견을 비워 두고 계속해도 된다. Explore에서 등록 분석에 포함된 적격 관점과 제공된 이유·조건을 확인한다. |
| 고른 관점에 같은 질문 던지기 | 하나를 고르면 1:1, 둘이나 셋을 고르면 자동 토론으로 들어간다. 질문 입력과 시작 후 각 관점의 입장과 상대에 대한 응답이 순서대로 나타난다. |
| 토론의 결과와 출처를 확인하기 | 결론에서 공동 주장과 남은 이견, 근거를 확인한다. 합의 Agent가 만들어지면 후속 질문을 한다. 합의 없음·검증 보류에서도 이미 나온 발언을 읽을 수 있다. |
| 자기 판단을 저장하고 다시 보기 | Reflect에서 현재 의견과 성찰을 직접 저장한다. 다시 열어 저장본과 연결한 대화를 확인한다. |

처음에는 Chromium의 새 프로필을 사용한다. 정상 흐름을 한 번 수행한 뒤 **빈 질문,
중복 시작, 토론 중 새로고침, 다른 Agent로 바꾸기, 합의 없음/검증 보류, 성찰 재열람**을
확인한다. 연결 오류가 났던 페이지에서 다시 새로고침했을 때 이전 세션과 진행했던 토론이
복원되어야 한다.

실제 질문을 검증할 서버에서는 시험 기기에서 `/mvp`에 접속하고 새 토론이 시작되는지
먼저 확인한다. 서버의 생성 가능 시간대가 QA 시간과 겹치는지도 확인한다. 화면 동작만
검증할 때는 저장소 루트에서 아래 무료 합성 모드를 실행할 수 있다. 출력된 로컬 주소에
`/mvp`를 붙여 접속하고, 다른 결론은 `--debate-result no-consensus` 또는
`--debate-result hold`로 확인한다.

```bash
PYTHONPATH=src python -m experiments.mvp_browser_fixture runs/qa-local --automatic-debate
```

### 핵심 과업이 주는 가치

사용자가 댓글에서 구별되는 입장과 조건을 찾고, 원문으로 확인한 뒤
토론에서 나온 새로운 조건이나 남은 질문을 자신의 판단에 반영하는지 확인한다.
의견을 바꿨는지는 성공 기준에 넣지 않는다.

| 과업 | 관찰 가능한 완료 기준 | 기록 |
| --- | --- | --- |
| Explore | 다른 관점 두 개를 자신의 말로 구별하고, 각 관점의 실제 원문을 연다. 이유가 확인되지 않으면 그 한계를 알아볼 수 있다. | 성공·부분·실패, 원문을 열기까지 시간·도움 여부 |
| Converse | 새 질문에 두 관점이 어떻게 답했는지 설명한다. 원댓글에 나온 주장, AI가 제안한 조건, 결론이 보류된 이유를 구별한다. | 질문의 수치·조건 변경, 잘못된 출처 귀속, 미응답, 이견·보류를 찾았는지 |
| Reflect | 토론에서 판단에 참고할 차이, 한계 또는 이어서 알아볼 질문을 하나 정리하고 같은 기록을 다시 연다. | 작성·재열람 완료, 어떤 근거를 참고했는지 |

앱이 끝까지 열려도 질문의 수치·조건을 바꾸거나 원문에 없는 의미를 작성자에게 귀속하면
해당 답변은 품질 실패로 적는다. 합의가 보류된 경우에는 검증된 발언을 열고
성찰까지 이어갈 수 있는지를 확인한다. [실댓글 가치 QA 결과](MVP_REAL_VIDEO_VALIDATION.md#근거-확인과-판단을-중심으로-한-qa)

Explore의 원문 버튼은 카드를 눌러 여는 비교 창에 있으며, 카드 입장과 각 이유·조건에 연결된 검증 출처만 연다.
처음 의견을 비워도 비교 창에서 원문을 확인할 수 있고, 이때 비교 생성 요청은 보내지 않는다. 토론 생성과 독립 발언 검증은 질문의 수치,
단위, 기준 시간과 대상 범위를 비교한다. 질문을 보존한 환산이나 명시적인 대안 비교는
가능하다. 질문을 바꿔 다시 진술한 요지는 보류하며, 유효한 요지와 이전 기록을 보존한다.
주간 총시간을 명시한 질문의 동일 값을 일일 시간으로 그대로 옮긴 AI 추론은
게시 전에 검사한다. 수치가 여러 개거나 해석이 필요한 형태는 독립 의미 판정을 사용한다.

## 비교할 과업

같은 영상과 같은 댓글 범위를 사용한다. 원문 목록에는 부모 문맥도 함께 제공하고,
Re.View에는 그 자료에서 자동 생성한 전체 가용 관점을 제공한다. 좋은 Agent만 골라 보여주지 않는다.
처리 범위·분석 revision·자료 사용기한·미검증 범위를 시작 전에 기록한다.

참여자는 먼저 초기 의견을 적고 두 방식을 각각4분씩 사용한다. 절반은 원문 읽기부터,
나머지는 Re.View부터 시작한다. 순서와 두 번째 과업의 학습 효과를 기록한다.
첫 소규모 확인은 결함을 찾는 용도이며 통계적 우월성이나 시장 경쟁력의 증명이 아니다.

1. 댓글의 서로 다른 관점 세 가지를 설명한다. 자료에 세 가지가 없으면 확인한 수와 한계를 적는다.
2. 각 관점의 이유를 말하고, 실제 원문으로 두 사례를 확인한다.
3. 조건·예외·보류 중 한 가지를 찾아 설명한다. 확인하지 못한 부분은 모른다고 표시한다.
4. Re.View에서는 한 관점에 후속 질문을 하고, 가능하면 그룹 대화를 확인한다.
5. 현재 의견과 회고를 저장하고 새로고침 후 다시 연다. 의견 변화가 없어도 성공이다.

## 남길 관측

| 항목 | 기록 기준 |
| --- | --- |
| 관점 구별 | 서로 다른 실제 주장 수와 혼동/누락. 사람이 원문과 대조 |
| 이유 귀속 | 제시한 이유가 해당 작성자·관점의 것인지, 다른 출처에서 옮겼는지 |
| 조건 보존 | 실제 조건을 보존했는지, 무조건 주장으로 바꿨는지 |
| 원문 확인 | 두 출처를 찾는 데 걸린 시간과 잘못 연결한 수 |
| 사용성 | 각 과업 완료/실패·막힌 화면·오류 메시지·완료 시간 |
| 자기 생각 | 유지/변화/새로운 질문을 사용자가 표현했는지. 변화 방향은 채점하지 않음 |
| 비용 | 최초 Factory와 분리한 비교·질문·그룹·회고 실청구, 재열람 신규 호출 수 |

참여자 식별은 임의 번호만 사용한다. 키·세션 token·개인 의견·원문 대화는 공개 Git/PR에 넣지 않는다.
유료 과업은 동결한 공유 장부·실행 상한·기한 안에서만 수행하며, 남은 예산으로 못 하면 미실시로 기록한다.
실패한 과업을 성공한 참여자로 대체하거나 좋은 결과만 합산하지 않는다.

결과에는 방식별 원자료 수·진행 순서·실패·제한을 함께 적는다. 실제 참여자 확인 전까지
‘이해가 향상됐다’, ‘일반 댓글 읽기보다 낫다’, ‘경쟁력이 입증됐다’고 결론 내리지 않는다.
