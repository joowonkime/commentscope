## 후속단계를 포함한 시나리오

같은고정deployment의 기존실제응답으로 stage별단가를 얻었다. 동일stage에 여러참조가 있으면
더높은 평균단가를 선택했다. 논거참조에는 과거 합성G1, fact에는 기존40건, runtime에는 기존6응답이
포함된다. 다른자료/prompt에 대한 **비용참조**이며 새실행의 의미성공/정확한단가를 승계하지 않는다.

현재96개는literal node265개, 갱신999개는2,733개다. 이는 구문 단위이며 유효관점/지지수가 아니다.
논거대상source의 평균node밀도·source당core owner1개·과거graph요청9/8source를 가정해 계산했다.
실제 긴댓글·복수owner·사실전제·가격/cache 변화에 따라 비용과요청수가 달라진다.

## 고정할 구조와 개선할 전송

원문→공통제안→독립지지→개별논거/사실→Compiler→불변bundle→제품의 책임은 구조v1로고정한다.
현재개별 pair/node 전송을 대량서비스의 최종방식으로 채택하지 않는다. 같은원문의 여러target/
literal node를 한request에 묶는 전송을 다음비교 대상으로 두며, 기존역할 자체를 다시섞지 않는다.

| 후보 최적화 | 유지할 책임 | 비교해야 할 것 |
| --- | --- | --- |
| 한source의 여러후보 raw판정 묶기 | 각candidate의범위·저자·근거·조건과 긍정edge별독립후속검사 | 행누락/다른ID/조건전이·새batch영수증·실제청구 |
| 한source의 node metadata 묶기 | 원문불변·각literal unit별분류와별도blind 감사 | 긴원문출력용량·귀속·unresolved·기존guard·실제청구 |
| 감사 입력의 같은원문 반복 전송 줄이기 | source-only관측과core관계판정의 입력독립성 | 선언/이전답 누출·필수전제누락·서로다른역할의자기승인 |

이최적화들은 아직구현/실측채택하지 않았다. 요청수나byte감소만으로 절감액을 확정하지 않는다.
독립 검증을 없애거나 원문/조건/필수사실을 버리는 비용절감은 채택하지 않는다.

## 이번에 구현한 실행 제어

`tools/plan_factory_cost.py`는 기존응답 감사와전체stage비용 preview를 유료호출없이 생성한다.
공통관점 development 본실행은 proposal 후 고정한 `cost-preflight.json`이 있어야 한다. 누락/미측정stage·다른model/
변경된plan/후보/profile·예산부족·pending checkpoint는 다음호출 전에 거절한다.
실행중고유request는 stage상한으로 제한하며 동일완료checkpoint는 다시차감하지 않는다.
금융권한/원trial상한/기존장부/request별wire예약은그대로다. 새비용계획으로 돈이추가되지 않는다.

새실제실행은 하지 않았다. 정식G1실패·G2/G3/G4차단과MVP미완료를유지한다. 구조v1을고정한것은
역할과입출력경계를고정한것이며, 현재단가·의미정확성·서비스경쟁력이검증됐다는뜻이아니다.
