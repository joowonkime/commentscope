## 고정 입력과 완료 산출물

공식 API의 최대240개 bounded snapshot에서 canonical ID의 고정 hash 순으로 root64/reply32,
합계96개를 모델 처리한다. 별도 root16/reply8은 discovery/지지 집계에서 제외한24개 확인용으로 보존한다.
내용·주장·기존 정답으로 뽑지 않는다. 부모 문맥은 유지하며 부모를 자식의 지지로 더하지 않는다.
표시 댓글938개 전체 분석으로 소개하지 않는다. 수집 범위·제한·원문 hash·사용기한을 기록한다.

같은 역할의 자동 발견→후보 검색→Jev M1→Sol M2→원문 증거 그래프/전체 감사→Compiler를 사용한다.
검색은 후보당 최대12출처, 전체192쌍/48출처다. 미평가 후보/댓글은 비지지나 노이즈가 아니다.
관점 수를 고정하거나 특정 Agent를 직접 작성하지 않는다. 최소2서로 다른 관점·각3유효지지,
출처 귀속·조건·필수 사실은 유지한다. 실패한 source/질문을 재시도하거나 결과에 맞춰 문턱을 바꾸지 않는다.

신규 주제의 사실 근거는 공식 UKRI 원문을 별도 취득해 exact span과 함께 공급한다.
UKRI의2022년 영국 시범사업에 대한 범위를 모든 업종/국가/개인 경험의 사실 확인으로 확장하지 않는다.
필수 근거가 없으면 보류하며 Kela UBI 자료를 주4일제의 근거로 사용하지 않는다.

출력은 자동 산출된 전체 적격 Agent, 각 지지/이유/조건/미검증 범위, 모든 Agent의 기존3질문과
추가4질문(32/40시간,업종 제약,실제 반론/한계,모든 업종에 보장된 생산성 수치)이다.
기존 runtime의6질문 한도를 유지하며 표준3질문과 기능4질문은 별도 세션에서 실행한다.
7질문 연속 대화가 통과했다고 보고하지 않는다. 세션 그룹과 다른 이력 불변을 기록한다.
실제 답변·원문·인용·필수 전제와 profile 간 차이를 대조한다. answered/abstain 형식만으로 유용성을 승인하지 않는다.
고정 질문 밖의 초행 사용자 검증·그룹/성찰·전체r5는 별도 미완료로 유지한다.

## 비용과 실행 경계

팀 누적150달러의 동일 DB/계정/금융owner와 과거 보수 차감을 유지한다. 새 금융 owner나
추가150달러를 만들지 않는다. 새 현재 지시에 대한3시간/최대1200신규물리요청의 실행만 등록한다.
모든 모델/provider/가격 상한·원문/문서/runner/code hash·stage 상한·기한을 동결한다.
현재 키/가격/장부의 미정산0·자원·입력을 확인하고 코드/회귀/양OS CI 통과 뒤 호출한다.
댓글96개와 검색192쌍은 물리요청 수와 다르다. 동적 의미 단위 때문에 상한에 닿으면 미완료로 기록한다.
요청마다 예약으로 누적 한도를 지키고 실제 소모를 분리 집계한다. 원가/시간은 실행 후 실측하며
다른 주제·전체938·3천 개 비용으로 외삽하지 않는다. 실패/모호한 정산을 새 호출로 숨기지 않는다.

정산 증거가 있는 기존 graph length 실패는 무수정 보류로 넘기고 다음 작업을 진행한다.
미정산/출처 불명 실패는 중단한다. 기존 만료 C/B/확대 실행을 재개하거나 과거 응답을 섞지 않는다.
완료된 실행은 재진입해도 원문/완료 hash를 대조하고 결과를 읽기만 한다.
