## 같은 설정에서 달라진 지점

두 실행 모두 같은4관점과 집계 지지 집합을 얻었다. 의무화5원문, 자율 유지3원문,
수수료 면제 조건부2원문, 접근성1원문이다. 집계 지지11개를 모두 대조했고 잘못된 지지의
승격은 관찰하지 못했다. 조건부/단일출처 후보는 남지만3출처 Agent 기준에는 미달한다.
이 작은 개발자 대조를 전체 댓글 정확도나 검증률로 환산하지 않는다.

차이는 **지지 판정 이후 논거의 입장 정렬**이었다.

- fresh A에서는 의무화 지지5원문 중3개가 보류돼 상세검증 완료 출처가2개였다.
  같은 원문의 별도 시행 시점 주장에 대한 불확실성이 해당 후보의 보류로 이어졌고,
  직접적인 명령형/한국어 지지는 대상 범위가 불명확하다는 관측으로 보류됐다.
- fresh B에서는 시행 시점 주장의 정렬 관측이 달라져 해당 원문이 완료됐다.
  다른2원문의 보류는 유지됐지만 완료 출처가3개가 되어 두 번째 Agent가 생성됐다.

현재 이 정렬 제안은 GPT-5.2의 추출 역할에 속하고, 독립 귀속/논거 검사는 Sol이 수행한다.
따라서 Jev M1 결과만 좋아도 Agent 생성의 안정성이 확보되는 구조는 아니다.
판정 책임·필수 전제·후보별 완전성의 결합을 일반적인 사례로 검토할 필요가 있다.
이 관측을 이유로 불확실한 원문을 자동 승인하거나 실행 사이에 prompt를 조정하지 않았다.

모든 실제 답변은 각 Agent의 허용 원문 항목을 선택했다. 자율 유지의 선택 자유 이유와
의무화의 공공 안전 이유를 서로의 출처에 옮기지 않았다. 원문에 없는 정확한 연간비용/
사고 감소율 질문은 보류했다. 이는 고정3질문의 근거 유지 검사이며 일반 대화 적절성,
Explore·그룹·Reflect의 사용자 검증은 아니다. 공개 profile에 검증할 외부 사실은 없어
합성 두 실행의 facts 단계는 비어 있다. 사실 검증 정확도를 새로 확인한 것으로 보고하지 않는다.

## 실제 댓글에서는 왜 Agent가 없었나

24원문(16root/8reply)을 발견에 사용하고12source·72pair를 검사했다. 범위 내 가능한
24×8=192관계 중120개는 미평가이고, 한 후보는 선택쌍0개다. 이를 반대/무지지로 바꾸지 않는다.
최종 집계 지지는6후보에 각각1개, 나머지2후보에0개였다. 모든6개 지지 연결을 원문과
대조했으며 잘못된 지지 승격은 관찰하지 못했다. 원문의 주장이 외부 사실로 참이라는 뜻은 아니다.

두 종류의 보류를 함께 관찰했다.

- 명시적인 다수 수혜 예측 원문은 Jev가 supported를 선택했으나 population scope를 changed로
  관측해 host가 보류했다. 개발자 대조에서는 유효 지지 누락으로 보인다. 이를 복구해도 해당 후보의
  지지는2개이므로 이 한 오류만 수정해서는 Agent가 생기지 않는다.
- 허구 세계를 설명한 답글도 raw supported였지만 world/scope/자기근거 guard가 보류했다.
  이 보류는 필요한 보호다. 첫 누락을 고치려고 guard를 일괄 완화하면 잘못된 지지를 허용한다.

parent를 지칭하는 짧은 실제 도입 현황 답글도 uncertainty로 남아, 문맥 해석의 누락을 관찰했다.
다만 그 후보 역시 단일출처다. 현재 표본의 이질성/크기, 공통 후보의 추상화 수준, 선택 검색,
보수적인 관계 관측이 함께 작용한다. 이 실행만으로 어느 하나가 전체 실패의 원인이라고 확정하지 않는다.
집계3개에 도달한 후보가 없어 논거 추출·core·audit·facts·runtime 단계는 실행되지 않았다.
실제 자료에서의 완성된 Agent 단가나 답변 품질을 측정한 결과가 아니다.

별도 합성 dependency 가격 측정1건은 $0.004296250였다. 합성 두 실행과 이 부품의 합계는

fresh A의 Jev48건은 $0.007225344로 전체의2.34%, 논거 구성/검증은 $0.206543750로66.82%였다.

전체 서비스 절감률로 비교하지 않는다.

fresh B의 비용 감소도 구조 개선이 아니다. 코드는 동일했고 공급자 prompt cache가 달랐다.
기록된 cached/input token은 A=47,387/152,580, B=87,762/157,168이었다.
각 frozen plan에서 모델 응답은 새로 받았고, 앞 실행의 의미 결과를 끼워 넣지 않았다.

A 약49분, B 약10분이다. A에는 host commit/disk 부족과 환경 복구 대기가 포함되고,
B에도 proposal/비용검토/재개·자원관측 시간이 포함된다. 실시간 서비스 응답시간이나 p95가 아니다.
실제24의 API elapsed 합은 약187초, 첫 요청부터 완료까지는 약6분이었다.
논거/Agent/runtime에 도달하지 않아 합성 실행보다 저렴하고 짧은 것을 최적화 효과로 보고하지 않는다.
로컬 모델을 로딩하지 않았고, 자원 보호 기준을 낮추지 않았다.
