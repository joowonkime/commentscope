# 실제 bundle 제품 시험의 동일 예산 연결

TASK-017, REQ-008/009/010. 상세설계 v24. 구현 전 계약이며 실제 제품 성공을 의미하지 않는다.

공통관점 실험에서 생성한 실제 bundle을 개발 화면으로 확인하는 비용도 같은 trial의 합계$1.50 안에 둔다.
기존 제품 cycle은 제품 task·모델·종료시각·추가비용 한도를 계속 제한한다. 원$8 owner와 총$50
장부 및 과거 보수적 차감도 유지한다. 새 서버 plan이나 세션으로 어느 한도도 초기화하지 않는다.

## 입력과 책임

- `serve_mvp prepare --factory-trial <기존 trial>`은 선택 기능이다. 기존 제품 실행은 동일 동작이다.
- Factory plan과 trial의 원 owner/모델/공유정책을 일치시킨다. 개발산출물의 모든 compiler profile을
  그대로 가져오며 정식 admission이나 품질승인으로 승격하지 않는다.
- 연결 anchor를 제품 cycle 옆에 최초1회만 고정한다. 같은 cycle의 두 번째 서버도 같은 anchor를 쓴다.
  anchor는 기존 cycle의 이미 지출한 금액, trial 원 owner의 당시 누적금액과 모든 hash를 보존한다.
- 원 owner 장부에 제품 비용도 차감한다. trial 시작값+$1.50, anchor 시작값+제품 cycle의 남은 한도,
  원 owner 상한과 총$50 중 하나라도 다음 요청을 예약할 수 없으면 거절한다.
- 같은 cycle의 기존 제품 서버는 연결 시 종료한다. anchor 이후 기존 독립 cycle의 지출이 바뀌면
  연결 실행도 중단한다. 읽기·수동 저장은 계속 가능하며 자동 재전송하지 않는다.
- trial/제품 cycle 중 먼저 끝나는 종료시각을 따른다. Factory 검증 중에는 제품 유료 호출을 실행하지 않는다.

## 요청 예약

제품도 기존 `WireBudget`으로 실제 전송 JSON의 UTF-8 크기, provider 여유, 답변+reasoning 토큰,
고정 가격 상한을 예약한다. 전체 모델 context를 모든 질문의 입력 길이로 계산하지 않는다.
화면 room 예약과 실제 지급 요청은 동일 할당/상한 공식을 사용한다. 예약 가능한 금액을 실제 비용이라고 표시하지 않는다.

## 검사와 실행 조건

오프라인: 기존 제품 호출 보존, 다른 owner/모델/trial 연결 거절, 재준비 시 anchor 유지,
Factory/제품 공동1.50 차감, 제품 cycle 과거비용 보존, 종료 후 새호출 거절/읽기 허용,
wire 예약과 실제 budget 일치 및 적은 잔액에서 context 전체 예약을 요구하지 않는 사례를 확인한다.

실제 실행:96개 개발 검증의 자동 산출물과 모든 Agent의3질문을 먼저 검토한다. 최소2개 적격 Agent가
없으면 제품 자료를 교체하지 않는다. 적격한 경우 localhost에서 해당 주제의 초기/현재 의견을
명시해 Explore→그룹/1:1→Reflect·사용자수정·저장·재열람을 최대9호출로 확인한다.
빈 성찰 범주는 유효하며 관점수/범주를 인위적으로 채우지 않는다. 실패 재시도나 별도 cap 생성은 없다.

명세검사·모의검사·실제 기능 흐름·의미 품질·999개 정식gate는 서로 다른 증거다.

구현 후 오프라인 결과: 관련80개 검사 통과. 원문96 검증은 별도 진행 중이며, 새제품연결 유료호출0이다. 실제 적격 bundle 확인 전에는 새 제품 서버를 준비하거나 기존 화면 자료를 교체하지 않는다.
