# 최신 관점 모드의 웹 서버 연결

TASK-028 / REQ-005·006·008·009·010 / DEC-028.
사용자는 선정 영상의 실제 Agent를 비개발자도 기존 화면에서 쓰도록 연결하고 기존 작업을 보존하도록 요청했다.
이 문서는 구현 계약이며 아래 검증을 실행하기 전에는 완료 증거가 아니다.
후속 PR109/110의 구현·양OS CI와 실제180댓글/제품 검증은
[최종 연결 결과](PREPARED_VIDEO_WEB_RESULT.md)에 구별해 기록했다.

## 확인한 공백과 변경 범위

`ProductApp`·메시지 저장·`/mvp`의 provenance 표시는 새 모드를 지원한다.
그러나 `serve_mvp.build()`는 `decision`/`decision_reservation`을 전달하지 않아
새 모드 bundle을 `Seeded analyses require typed verifier and reservation`으로 거절한다.
실험용 실행기가 제공하는 생성/판정 경계를 일반 웹 서버에도 연결한다.

- 기존 화면·API·기본3출처 경로·실험 원본·저장 DB를 보존한다. 새 DB/동결 실행 계획에서 확인한다.
- bundle의 명시적 admission policy로 새 모드를 식별한다. legacy bundle에 Jev 호출을 추가하지 않는다.
- 새 모드의 prepare는 고정 Jev deployment/가격·상태를 확인하고 plan에 동결한다. 추론하지 않는다.
- build는 동일 설정을 재확인하고 생성/판정 callback을 모두 연결한다. 설정 변경·누락은 추론 전에 거절한다.
- 생성과 판정은 같은 계정·기존 cycle/금융owner·공유 장부·기한·단일 실행 경계를 사용한다.
  새 서버나 room으로 예산·과거 비용을 초기화하지 않는다.
- 원문/문헌 인용·문단 귀속·조건·보류 기준은 기존 새 모드 계약을 따른다. 자동 재생성은 없다.
- 알려진 청구가 있는 실패도 room에 기록한다. 미확정 청구는 reconciliation으로 막고 자동 재전송하지 않는다.
- 브라우저 확인에는 합성 모드를 명확히 구별하며, 실제 댓글 품질이나 전체 MVP 완료로 승격하지 않는다.

## 기대 동작과 부정 사례

| 입력/상황 | 기대 동작 |
| --- | --- |
| legacy bundle | 기존 생성 경로, Jev prepare/build/추론 없음 |
| 명시적1출처 bundle | Sol 생성→Jev 관측→host 출처 결합→기존 화면 표시 |
| 검증 deployment 누락/변경 | prepare/build 또는 동결 검증에서 거절, 유료 호출0 |
| room에 생성+판정 예약 여유 부족 | 첫 생성 전 거절 |
| 기한 종료/미확정 청구 | 새 호출 차단, 기존 기록 읽기 유지 |
| 판정 거절/잘못된 응답 | 잘못된 문단 미게시, 이미 발생한 비용과 이전 게시 보존 |
| 같은 요청 재입력/새로고침 | 기존 결과 조회, 자동 새 청구 없음 |

## 고정 영상의 생성·제품 실행 계획

`tools/prepared_video_trial.py prepare/run/serve`는 등록 snapshot 전체를 한 번 분석하고 같은
계획의 자동 산출물을 기존 `/mvp`에 등록한다. 영상별 임의 persona나 모델 교체를 추가하지 않는다.
정해진 영상 ID만 허용하던 과거 실행기를 변경하지 않고 등록 snapshot에 재사용할 수 있는 경로다.

- 고정 입력: Jubilee `7AGa5z69zqU`, 수집180댓글 전체(원댓글100/답글80). canonical 중복은 기존 규칙대로 처리한다.
- 모델: 기존 고정 Sol 생성/검증, 외부 embedding, Jev membership/대화 관측. 로컬 생성 가중치는 로드하지 않는다.
- 검색: 후보당12원문·최대384관계/96상세원문. 발견 입력180개와 상세 판정 범위를 구별한다.
- 원문 논거: 기존 B1 전체원문/후보 certificate 계약을 유지한다. 후보별 오류의 원문 전체 전파는 알려진 한계로
  기록하며 새 영상 성공/실패만으로 원인 해결이나 정확도 개선을 주장하지 않는다.
- 문헌: 고등학교 수학에서 무제한/보호형 tutor를 비교한
  [Bastani 등, PNAS 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12232635/)와 대학 물리에서 설계된 tutor를 비교한
  [Kestin 등, Scientific Reports 2025](https://www.nature.com/articles/s41598-025-97652-6)의
  고정 발췌·정확한 구간을 모든 관점에 제공한다. 다른 표본/설계의 결과를 모든 AI·인지 능력에 일반화하지 않는다.
- 금융: 기존 누적150달러 계정/금융owner/과거 차감을 그대로 사용한다. 새150달러나 종료된48호출 잔여를 만들지 않는다.
  owner 안의 과거 모델 설정은 금융 이력이며 새 실행 모델을 배정하지 않는다. 새 plan이 현재 Sol/Jev와
  가격 상한을 별도로 고정·검증한다. 실제 prepare에서 두 모델을 같게 요구한 오류는 유료 호출 전에 발견했고,
  과거 모델이 다른 금융owner를 그대로 쓰면서 새 plan의 모델 변경은 계속 거절하는 회귀로 수정했다.
  새 요청의7시간·최대2400물리요청은 유한 실행 보호이며 실제 사용 목표나 단가 예측이 아니다.
  실제 청구 전마다 같은 장부의 가격 상한·예약·정산으로 남은 금액을 검사한다.
- 재진입: 완료된 생성 결과는 읽기 전용으로 검증한다. 중단된 생성은 자동 재실행하지 않는다.
  새 서버/room도 동일 금융owner·기한을 공유하고 중복 요청은 기존 결과를 읽는다.
- 현재 생성/판정 문단 제거 후 질문 충족성이 미확정인 부분 응답은 유용성 합격으로 세지 않는다.
  최소2개 실제 대조 관점이 없으면 억지 찬반을 만들거나 다른 모델로 반복하지 않고 원 결과를 기록한다.

비공개 원문·문헌 발췌·계획·정산·사용자 대화는 `runs/`에 보존한다. 이 계약/검사와 실제 모델
관측을 구별하며, 고정 비교/1:1·그룹/성찰과 초행 QA 결과가 있어야 제품 연결 범위를 갱신한다.

## 실제 실행 전 로컬 구현 확인

일반 실행기와 등록 영상 실행기에 생성/판정 callback·동결 verifier·공유 장부 정산을 구현했다.
기존 HTML/CSS/JS와 API 경로를 교체하지 않았다. HTTP로 시작한 새모드1:1이 생성과 판정의
두 비용을 같은 금융owner에 기록하고, 등록 영상 실행기의 실제 adapter/strict schema 경로도
합성 응답으로 확인했다. 유료 호출0이다.

- 관련64개 검사 통과. 생성 전 예약·verifier 누락/변경·만료·중복 요청·실패 비용·원본/금융 변조를 포함한다.
- 기존 Factory945개/277.955초 통과, 신규 등록 영상 실행기14개 별도 통과.
  해당14개를 필수 Factory 명령에도 포함했다. 첫 Factory 시도는143으로 중단됐고 성공으로 세지 않았다.
- Chromium 새모드25항목·기존 Node10개 통과. 댓글/AI추론/외부문헌 표시·그룹·원문·성찰·재열람을 포함한다.
- 이 시점에는 실제 새영상 Agent·실제 모델 브라우저를 확인하지 않았다.
  후속 결과는 위 연결 결과를 따른다. 초행 사용자 QA·공개 배포는 여전히 미완료다.

후속 금융/model 결합 수정은 관련65개 검사를 통과했다. 실제 기존owner(gpt-5.2 이력)와
현재 Sol/Jev 설정으로 prepare/guard·provider metadata를 확인했고, 추론 함수를 차단한
검사에서 새 모델 호출0·장부 불변을 확인했다. 검사용 임시 계획은 제거했으며 실제 실행 grant로 쓰지 않는다.
