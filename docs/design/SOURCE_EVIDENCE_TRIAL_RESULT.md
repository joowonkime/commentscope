## 확인한 구조적 문제

1. observer/candidate의 `issue_codes` enum에는 정상 상태가 있으나 v1 구현은
   비어 있지 않은 모든 코드를 차단한다. 출처·후보 연결의 두 무료 회귀로 재현했다.
2. 독립적으로 선택한 scope 구간·양태 등의 완전 일치를 승인 조건으로 삼는다.
   의미가 양립하는 annotation 차이와 실제 의미 충돌이 같은 전체 출처 보류가 된다.
   desired/categorical의 구분도 세계/희망과 확신 강도를 한 축에 넣고 있다.
   14개 graph 전체에서 정상 코드만 제거한 결정적 재생도 complete0개였다.
   이 재생은 신규 v2 실행이나 의미 승인 증거가 아니다.
3. 실제 경계 누락·혼합 해석·필수 관계 미해결·타입/offset 오류도 있다.
   모든 차이를 annotation 차이로 처리하거나 강한 모델로 해결된다고 단정하지 않는다.
4. legacy 의존성 검증은 모든 unit/target 쌍을 조사한다.18개 record에서1,731질문/
   물리요청116개를 구성하며,29-unit 원문 하나가930질문/59요청을 차지한다.
   실제로91개 의존성 응답에$1.5948085가 들었다(A의 확인 요금 약64%).
   질문 수는 `U*(U-1+C)+2*U+C+(U+C)`이며 현재 chat도16질문씩 나눈다.
5. 현재 고정 선언으로 게시가 불가능한 출처에도 이 후속 검증을 계속한다.
   이는 [조기 종료 계약](SOURCE_AUDIT_PREFLIGHT.md)에서 별도로 수정한다.

## 구현한 무료 수정과 효과의 한계

- v2는 정상 status code를 차단 오류와 구별한다. 명시적 실패/unknown·누락·타입/scope/edge
  불일치·필수 사실·전체 source 완전성은 유지한다. 원 v1 증거를 v2 증거로 승인하지 않는다.
- 재개 시 `resources/attempt-NNNN`을 사용해 기존 감시 기록을 덮어쓰지 않는다.
- legacy split typed 경로는 기존 승인 규칙상 모든 후보가 불가능한 출처의 후속
  owner/dependency/source-audit 호출만 생략한다. 원 record/map/보류·필수 core source는 유지한다.
  다른 후보에서는 가능한 SCOPABLE source는 계속 검토한다.
- 실제 A record의 정적 진단에서는13개가 이 조건에 해당한다. 후속 dependency116→5,
  owner22→8,source audit task116→13이다. 이미 발생한 비용은 그대로 보존한다.
  이 비율을 다른 자료의 절감률·전체 비용·정확도로 일반화하지 않는다.

정상 코드/자원 로그 수정본의 관련50개·Factory793개가 먼저 통과했다.
추가 조기 종료 회귀는 동일 게시 bundle/Agent,원문·map 보존,변조 거절,
다른 후보의 유효 source 보존을 검사한다. 최종 Factory798개가414.089초에 통과했다.
수정본의 실제 v2 Agent/품질 비교는 실행하지 않았다.

## 남은 작업

annotation 완전 일치를 의미 보존 검증으로 대체하는 계약과,유효한 긴 원문에도 적용되는
희소 의존성 검증이 필요하다. 이번 조기 종료는 유효 원문의 제곱 복잡도를 바꾸지 않는다.
새 계약의 정상/부정 통제·정적 workload/가격 상한을 먼저 고정한 뒤 실제 비교를 등록한다.
