## 확인된 병목과 아직 모르는 것

원문 단위16개 중8개에서 단어 내부를 자르는 문자 경계가 기계적으로 관측됐다.
이는 정답률이 아니며 모든 경계가 의미 오류라고 자동 판정하지 않는다. 짧은 실제 문장에서도
누락된 주어/한정 표현과 경계 문제가 확인됐다. LLM에게 숫자 위치를 계산시키는 표현 방식이 취약하다.

감사에서 fail/unknown으로 기록된 단위별 필드는 scope29·reason16·boundary14·qualifier9·world8 등이다.
여러 필드가 같은 원인에 반응하므로 독립 실패 수나 원인별 기여율로 해석하지 않는다.
전체16개에 대한 독립 사람 gold·오보류율은 없다. 댓글에 주장이 부족하다는 결론도 내릴 수 없다.

호스트가 거절하는 유형 조합을 현 제안 schema가 허용하고, 필수 전제 선택란에는 예시/이유 등
다른 관계 ID도 노출한다. 그 결과 형식적으로 생성 가능한 응답이 host 계약에서는 거절된다.
후보 연결1건만 고쳐도 나머지 출처 실패와 지지 부족은 남는다. 단일 출처 구제를 개선으로 보고하지 않는다.

## 후속 구현의 일반 원칙

F1~F5/Compiler/Runtime 책임과 최소 지지·원문 전체 보존·필수 사실 검사는 유지한다.
다음 표현/형식 후보는 아래 책임을 구체화해 무료 정상/부정 회귀부터 확인한다.

1. 모델은 원문 조각과 의미를 선택하고, host가 정확히 일치하는 원문 조각을 불변 ID/Unicode 위치에 결합한다.
   모호한 반복·없는 문자열·부모에서 빌린 주장은 보류한다. fuzzy 보정이나 의미 수리는 하지 않는다.
2. 의미와 무관하게 결정 가능한 유형 일관성·허용 edge 목록은 schema/host가 책임진다.
   unknown을 억지로 pass로 바꾸지 않으며 작성자 이유와 필수 사실 전제를 구분한다.
3. 감사 정상 통제와 실제 생성의 검증을 분리한다. 새 모델 응답 전에 자료·wire·판정·금액/기한을 고정한다.
   표현 변경의 효과와 모델 변경의 효과는 별도로 측정하며 한 실패에 맞춘 유료 반복을 하지 않는다.

이 원칙은 다음 후보이며 구현 완료나 효과 입증이 아니다. 조건 구분·재호출 방지 구현은 유지하지만
이번 v4 자체의 생성 품질 채택은 보류한다. 48개 paired 개발/전이·전체 r5·3000개 단가/속도·TA 사용성도 미검증이다.
