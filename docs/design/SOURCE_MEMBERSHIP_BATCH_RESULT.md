# 원문별 membership 전송 최적화 결과

TASK-017, REQ-001/002/008/010. [계약](SOURCE_MEMBERSHIP_BATCH.md), [책임 구조v1](ARCHITECTURE_BASELINE.md).
이 결과는 무료 구현·요청 크기 비교다. 실제 모델 품질이나 달러 절감의 측정이 아니다.

## 구현한 범위

- 원문 하나와 최대6개 후보의 판정을 한 요청으로 전달하는 선택 경로를 추가했다.
- 전체 batch 요청/원본 provider 응답과 각 행의 출처를 보존한다. 단건 영수증을 만들어내지 않는다.
- 같은 실행의 정확한 proof를 재사용한다. 실패한 의미 입력은 후보 provenance/phase가 바뀌어도
  다시 결제하지 않는다. 새로운 의미 입력과 기존 완료 proof의 결합은 구별한다.
- 기존 WORLD_CONTEXT host 검사와 긍정 행의 독립 own-evidence 검사, 논거·사실·Agent 검사는 유지한다.
- 별도 비용 stage `membership-source-batch`를 추가한 비용 형식v2를 사용한다. scalar 단가를
  batch 단가로 쓰지 않으며 필요한 packet 폭을 측정하지 않은 profile도 채택하지 않는다.
  v1 비용 파일은 보존하고 필요하면 원래 archive를 무료로 다시 감사한다.
- 기본 경로는 기존 scalar다. 새로운 shared development plan의 `prepare --batch-membership`으로
  명시적으로 선택한다. 만료된 시간·trial 상한·정식 gate를 변경하거나 과거 plan을 재태깅하지 않는다.

## 저장 요청 비교

이전 실제96 개발 실행의 완료된 membership 요청350건만 대상으로 삼았다. 미평가130쌍,
미완료 요청1건, 도달하지 못한 논거·Agent/runtime 단계는 결과에 포함하지 않았다.
원래 요청·응답·고정 코드 archive·checkpoint hash를 검사한 뒤 같은 source/context/world와
같은 처리 phase에서만 묶었다. 역할 별칭으로 phase가 모호한10건은 단건으로 남겼다.

| 측정 항목 | 기존 단건 | 묶음 전송 구성 | 감소 |
| --- | ---: | ---: | ---: |
| 물리 요청 수 | 350 | 137 | 60.9% |
| provider JSON UTF-8 전송량 | 3,643,157 bytes | 1,619,210 bytes | 55.6% |
| 추론 포함 출력 예약 상한 | 492,800 tokens | 274,688 tokens | 44.3% |
| 판정 대상 쌍 | 350 | 350 | 대상 보존 |

137개는 initial phase96개, expansion31개, 모호한 phase10개로 구성했다. 최대6개 제한 안에서
이번 완료 자료의 실제 묶음 폭은1~3개다. 새 모델 응답을 생성하거나 기존 응답으로 새 품질 점수를
만들지 않았다. 전체480쌍이나999개 처리 비용을 이 부분 결과로 환산하지 않는다.
기존 요청에는 provider prompt cache가 많이 적용됐으므로 호출 감소율은 달러 절감률과 다르다.

무료 재현:

```bash
python tools/compare_membership_transport.py runs/previous-shared-run \
  --output runs/batch-sizing/comparison.json
```

출력은 Git 제외한 개인 실행 자료다. 원래 모델 응답을 새 Factory 입력으로 재사용하지 않는다.

## 검증과 남은 범위

필수 Factory 회귀검사684개를 통과했다. 정상/누락/중복/외부 ID, 원문·후보·world·전체 영수증 변조, 보고된 속성의 오귀속, 독립 evidence
거절, 실패한 pair 재과금 방지, stage 예산, phase 별칭의 무료 비교 경계를 합성 검사한다.
합성 source6개에서 서로 다른 Agent2개·각3지지와6회 runtime까지 이어지는 개발 경로를 확인했다.
이는 실제 댓글의 지지·논거·사실 정확도나 기존 r5 합격을 입증하지 않는다.

실제 batch 단가 및 fresh 의미 품질은 아직 미측정이다. 해당 단가가 없으면 전체 비용 admission을
차단한다. 기존 actual96 예산 중단과 정식G1~G4 차단을 유지한다. 이번 추가 유료 호출은0회/$0이다.

## 일반화와 추가 예산 판단

사용자는 이 비교가 특정 사례에 한정됐으므로 추가 한도를 요청하는 편이 맞는지 확인했다.
현재 증거는 한 영상/한 부분 실행의 전송량 구성이다. 실제 batch 청구액, 다른 영상의 효과,
전체 Factory 원가, 반복 실행 성공률, 운영 서비스 단가를 증명하지 않는다. 이 수치를 근거로
총50달러 안의 MVP 완성을 보장하거나 지원 요청 필요성을 부정할 수 없다.

추가 지원 검토는 합리적이지만 모델 비용만 늘리면 의미 품질도 해결된다는 근거는 없다.
[기존 비용 결과](FACTORY_COST_RESULT.md)의999개 시나리오 역시 일부 단계의 과거 실측 단가를
적용한 계산이며 누락된 비용이 있다. 지원 요청에는 확정 청구, 미계측 과거 비용의 보수적 차감,
남은 검증 범위와 추정/미측정을 구분한다. 현 자료만으로 필요한 추가액을 확정하지 않는다.
추가 한도를 실제로 승인받거나 기존 금융/시간 계약이 갱신되기 전에는 지출 상한을 올리지 않는다.
