## 고정 범위와 역할

원999 snapshot·같은6후보·신규104쌍/69출처를 고정한다. 원1536시도쌍 전체(실패/미응답 포함)를
제외한다. 재검색·후보 재작성·새 embedding·발견 호출은 없다. 다른297후보는 원본에 보존한다.
관계 원파일86MB는 스트리밍으로 해당6후보의 기존 기록만 추출하며 의미 판정을 바꾸지 않는다.

과거 C의 동일 graph 요청은 성공/실패 모두 다시 생성하지 않는다. 정확히 같은 source/route/request의

raw 없는 length 응답도 checkpoint·provider receipt·실제 정산 증명이 맞으면 원 실패로 기록하고
PriorRequestUnavailable 보류로 넘긴다. 값을 수리하거나 재시도하지 않는다. 미정산/모호한 응답은 중단한다.

## 실행/금융 경계

새 실행 시간은 등록부터 최대4시간, 신규 물리 요청 상한1800이다. 이는 논리104쌍과 다르며
동적 단위 수로 인해 상한에 닿으면 미완료로 기록한다. 원문/필수 사실을 잘라 완료시키지 않는다.
기존 누적150 DB·계정·opening·금융 owner와 이전 차감/보수 정산을 유지한다.
새 시간 계약은 현재 계속 지시에 한정되며 원 C/B의 종료 기한은 수정하지 않는다.
실제 호출 전 키/가격/provider·현재 장부·원 금융 행 hash와 미정산0을 확인한다.
추정 전체 원가/시간은 아직 미측정이다. 요청별 보수 예약이 한도를 넘으면 호출 전에 멈춘다.

실행 전 기존 Kela 사실 문서의30일 사용기한 경과를 발견했다. 공식 페이지의 공개 article API에서
동일 발행일/제목/22개 본문 문단 전체를 재취득·대조한다. HTML 공백만 비교 시 정규화하고
동결 text·선택 span·필수 사실은 바꾸지 않는다. 새 응답/URL/hash/취득 시각을 별도 영수증으로
보존하고 새 plan의 취득/만료 메타데이터만 갱신한다. 문단 누락·다른 URL·오래된 취득은 차단하며
원C 문서와 결과의 기한은 수정하지 않는다. API 껍데기 HTML만 받으면 재확인으로 인정하지 않는다.

기존 shared Session의 명시적 authorization_guard와 generic typed budget 확장 지점을 사용한다.
과거8/50달러 scoped_authorization이나 그 실행 권한을 변경/우회하지 않는다.
source code·실행기·고정 입력·cache index·새 grant를 plan SHA에 결합한다.
정적 입력은 준비/시작 시 전체 검증하고 원 응답은 사용 시 원 파일/hash/request/모델을 대조한다.
재사용·신규·실패/보류·실청구를 분리하고 전체 결과의 합성/실제/독립 평가 범위를 구별한다.
