# 팀 누적150달러와 이전 장부 이력의 연결

TASK-022 / DEC-011·017 / REQ-008·010.
사용자는 팀키150달러 증액 후 실험 진행을 요청했고,2026-11-12에는 충분한 잔여가 있는데
실험별6달러 상한을 둘 필요가 있는지 지적했다. 제안한6달러 확인은 철회한다.
현재 실행은 별도 소액 상한 대신 **이전 지출을 포함한 팀 누적150달러**와 실제 키 잔여를 따른다.
전체 실험을 완주하기 전에 매번 소액 상한을 새로 승인받지 않는다.

## 장부 변경 계약

- 기존 계정 ID·SQLite 파일·opening charge·calls·plans·resolutions를 그대로 유지한다.
- 일반 생성자/재개로 상한을 바꾸지 않는다. 명시적 `increase_limit` 경로에서만50→150을 기록한다.
- 사용자 지시·현재 키 한도 관측을 묶은 authorization SHA, 이전/새 한도, 관측 한도,
  변경 시각, 변경 전 청구액과 금융 이력 SHA를 `limit_revisions`에 남긴다.
- 관측된 키 한도를 초과하거나 active/unknown/over-ceiling 과금이 있으면 변경을 거절한다.
- 잔여/청구액·과거 손실을 환급하거나 새 DB/opening balance로 시작하지 않는다.
- 기존 owner별5/8/15달러 등 `plans.maximum`은 바꾸지 않는다. 종료된 실험이 재개되는 변경이 아니다.
- 오래된 ledger 인스턴스는 reserve/summary 시 거절한다. 새 현재 policy로 읽으면 과거 owner의
  청구/한도는 그대로 조회할 수 있다. 같은 authorization의 변경 재실행은 idempotent다.

기존50달러 policy 파일은 수정하지 않는다. 같은 DB·계정·opening을 가리키는150달러 현재 policy를 별도 등록한다.
새 검증은 이 현재 policy와 새 고정 요청/코드/자료/유한 기한을 연결한다.
새 owner의 run ceiling도 누적 계정 ceiling150을 넘지 않으며, 실제 예약은 계정 전체의
이전 청구·보수 차감·미확정·현재 키 잔여를 동시에 검사한다. owner를 새로 만들어도 총액이 초기화되지 않는다.

## 남기는 실행 제어

기존 원문·평가·가격·요청/응답·checkpoint/receipt·시간·자원·동시 실행 lock을 유지한다.
고정16개 통제 → 실제3개 profiling → 비용/품질을 확인한 나머지19출처 검증 순서는 보존한다.
16개만으로 모델 채택/r5/3000규모를 승인하지 않는다. unknown 비용과 미평가 관계는 여전히 unknown이다.
자동 retry/fallback/실패 한 건에 맞춘 유료 수정 반복은0이다. 모델/자료/판정 계약이 바뀌면 새 비교로 구별한다.

소액 상한 제거는 무한 실행 허가가 아니다. 정해진 자료·요청 집합·유한 기한과 누적150달러를 지킨다.

무료 관련68개(3.881초), 전체 Factory829개(293.346초)가 통과했다. 실제 계정 revision과 모델 결과는 별도 기록한다.
