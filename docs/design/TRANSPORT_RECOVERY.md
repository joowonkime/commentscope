# 종료된 공급자 오류의 정산·항목 보류 복구

TASK-018 / REQ-001·003·008·010. 현재999 development 실행의 운영 복구 계약이다.

## 문제와 경계

전체1536쌍 관측 후 논거 정렬 요청에서 공급자 HTTP503 연결 시간 초과가 발생했다.
2964개 성공 응답과1개 실패 checkpoint는 모두 저장됐지만 실패 요청의 실제 비용이 없어
원래 실행기가 미확정 요금을 보류하고 중단했다. 메모리·의미 기준·후보 수 문제와 구별한다.
단순 재실행은 같은 실패 checkpoint에서 다시 중단된다.

## 복구 계약

1. 원 plan/요청/실패 결과/checkpoint/시간장부의 error와 공유 금전장부의 scope·request를 대조한다.
   대상은 출력·usage가 없고 명시적 일시적 HTTP 오류인 종료 요청이다. 진행 중·응답 유실·다른plan·
   의미 판정 오류·새 요청을 자동으로 대상으로 삼지 않는다.
2. 증거를 불변 파일로 남기고 기존 예약 전액을 보수 차감으로 정산한다. 실제 비용0으로 처리하거나
   환불·예산 초기화·deadline 연장은 하지 않는다. 다른 예약/미확정이 있으면 새 호출을 막는다.
3. 새 복구 launcher는 원355개 source/원4개 실행 tool을 변경하지 않는다. 추가 launcher 자체와
   그 사본의 SHA, 원plan SHA, 오류 증거와 정확한 요청 식별자를 별도 불변 manifest에 결합한다.
   실행 control 확장이므로 원래 구현과 완전히 동일하다고 보고하지 않는다.
4. manifest에 등록되고 정산된 이전 실패 요청만 기존 `PriorRequestUnavailable` 보류로 전달한다.
   공급자 재호출·성공 응답 합성·누락 판정 채우기·긍정 지지 승격은 하지 않는다. 나머지 요청은
   원 Session/모델/prompt/schema/역할/정산·자원·호출상한을 그대로 지난다.
5. 새로운 공급자 오류는 원래처럼 중단한다. 자동 등록·재시도·fallback 루프를 만들지 않는다.
   보류된 정렬/근거가 필요한 출처·Agent는 기존 완전성/최소지지/사실 검사를 계속 충족해야 한다.
6. 원 completed 파일은 원 실행기가 작성하고, 별도 completion binding이 원 결과와 복구 manifest를
   결합한다. formal admission은 계속 false다. 성공 응답 비용과 보수 차감·실패 횟수를 분리한다.

원 계획·자료·모델·의미 기준·기존 예산/기한을 바꾸는 복구는 이 계약의 범위가 아니다.
외부 wrapper로 임의 응답을 주입하는 일반 실행 경로를 제공하지 않는다.

## 검사

합성 자료로 정확한 실패/요청/장부 결합, 보수 차감 유지, 재호출0, 정상 요청의 원 경로 통과,
진행 중/미정산/다른 요청/변조된 원본·manifest·launcher의 거부를 검사한다.
실제 재개는 모든 오프라인 검사와 기존 자원·자료·금융·남은 시간 검사 후 수행한다.
정식 품질 합격이나 독립 사람 gold를 뜻하지 않는다.
