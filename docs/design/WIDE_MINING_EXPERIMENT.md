## 설계 대조와 현재 계획

상위 발굴 설계는 넓은 원문 입력에서 관점을 발견하도록 했지만, 이전 `MINING_EXPERIMENT.md`는
합성12 fresh2회/실제24 development1회였다. 기존 실행기도 G1/G2/G3의 고정12/24/96을 골랐다.
`maximum_snapshot_comments=3000`은 입력 허용 상한이며 실제 입력 수가 아니다.
이전 실험과 결과는 보존한다. 그 계획을 현재 확대 실행의 명세로 사용하지 않는다.

현재 입력은 이미 승인·갱신된 같은 영상의 **등록 canonical999개 전체**다. 원문 raw1000개와
canonical999를 구별하고, 동의/반대/의미 여부를 보고 입력을 고르지 않는다. 수집을 다시 하거나
고정755/453을 바꾸지 않는다. 전체999개의 embedding과 발견을 수행한 뒤 후보별 근거를 검색한다.
선정된 원문만 세부 판정하는 것과 전체999개를 발견 입력으로 읽는 것을 따로 보고한다.

## 금융·기록 경계

원래8달러 owner와 작은 실험의1.50/추가3.00 문서는 종료된 이전 범위로 보존한다. 새 사용자 지시의
확대 단계는 별도 authorization을 만들되 원owner의 파일/hash, 당시 누적 scope 차감과 전체 장부의
개시 차감을 고정한다. 기존 지출을 환불·삭제·재분류하지 않는다. 새 단계의 추가15은 전체 장부의
기존 누적 차감에 더해지고, 원래 실행의8달러 cap이나 과거 deadline 파일을 수정하지 않는다.
기존에 구현한 completion phase와 같은 원장부/별도 명시적 단계 패턴이다.
팀 키150/운영장부50/과거owner8/새추가15을 하나의 잔액처럼 섞지 않는다.

시작 전 실제 key 한도/잔액·전역 예약/미확정0·등록 자료 기한·원본/코드/모델/provider를 확인한다.
모든 요청에 시간·자원·원장부·새단계 cap·가격·wire 예약·단계별 호출상한을 적용한다.
자료/코드/입력/모델이 바뀌거나 새 비용계획이 미측정·미충족이면 해당 요청 전에 중단한다.
